    1Part II at a glance

    Part II drives the worlds: reset some of them, snapshot and restore them, feed controls in, size the fixed buffers that contacts and constraint rows live in, read the sticky overflow bits when a buffer runs out, and give each world its own physics.

    2Resets

    Masked reset

    mjw.reset_data(m, d)                  # every world
done = wp.zeros(d.nworld, dtype=bool)
mjw.reset_data(m, d, reset=done)      # only where done[w]
mjw.forward(m, d)                     # derived data is stale

    Mask: shape (nworld,), bool or any int dtype; anything else raises ValueError. Writes qpos ← qpos0, mocap ← body pose, eq_active ← eq_active0; zeroes time, qvel, ctrl, act, warmstart, applied forces, sensordata, and clears d.overflow (Ch 8 §1).

    Keyframes, one per world

    mjw.reset_data_keyframe(m, d, 0)        # int: all worlds, must be valid
keys = wp.array(np.array([0, 1, -1, 1], np.int32))
mjw.reset_data_keyframe(m, d, keys)     # -1 (out of range): skip world
mjw.forward(m, d)

    Ch 8 §2; why forward after a reset: §3.

    4Control, mocap and equalities

    step1 / policy / step2

    mjw.step1(m, d)        # position + velocity, sensors fresh
policy(d.sensordata, d.ctrl)   # your kernel writes d.ctrl
mjw.step2(m, d)        # actuation, solve, integrate

    Under RK4, step2 integrates with Euler (Ch 8 §7).

    Control callback (works inside a graph)

    def control(m, d):
    wp.launch(pd_control, dim=d.nworld,
              inputs=[d.sensordata, 0.0, 20.0, 2.0],
              outputs=[d.ctrl])
m.callback.control = control
mjw.step(m, d)          # runs after sensor_vel, before actuation

    Python side effects run once at capture. Under RK4 it runs 4 times per step, 3 with stale sensors (Ch 8 §9). Catalogue of all 7 slots: Part VI sheet.

    Per-world inputs

    • d.mocap_pos (nworld, nmocap) vec3, d.mocap_quat: read by kinematics (Ch 8 §5).
    • d.eq_active (nworld, neq) bool: switch equality rows per world (Ch 8 §6).
    • ctrlrange clamps inside _actuator_force; d.ctrl keeps the raw value (Ch 8 §8).

    Device-side auto-reset

    mjw.step(m, d)
wp.launch(done_kernel, dim=d.nworld, ...)  # task done / timeout
nonfinite_reset(m, d, done)               # NaN guard (my_env)
mjw.reset_data(m, d, reset=done)
wp.launch(randomize, dim=d.nworld, ...)   # in place
mjw.forward(m, d)                         # unconditional: graph-safe

    MJWarp has no mj_checkPos/mj_checkVel and no auto-reset: add the guard (Ch 8 §10). Worlds as parallel rollouts for MPC: §11.

    KeywordCountsPerDefaultBit when full

    The defaults (io.py, 4.0.1)

    nconmax = max(nv*0.35*(nhfield>0)*10 + 45, 256*has_flex, 64*has_sdf, ncon)
njmax   = max(nv*2.26*(nhfield>0)*18 + 53, 512*has_flex, 256*has_sdf, nefc)
# rounded up to the ladder 16, 24, 32, 48, 64, 96, 128, ... 8192
LADDER = [(2 + k % 2) * 2 ** (k // 2 + 3) for k in range(19)]

    So every rigid model without heightfield, flex or SDF gets nconmax=48, njmax=64, a ball and a humanoid alike. A 6-box tower needs 96 rows and overflows the default.

    Recipe

    1. Roll out with generous budgets; record per world the max contacts (np.bincount(contact.worldid)) and the max nefc.
    2. Add 25% (more if DR can make scenes denser).
    3. Round up to the ladder.
    4. Check d.overflow.numpy().any() in the real run.

    Rows per contact: 2(condim-1) pyramidal, condim elliptic. Memory: dense efc.J is nworld × njmax_pad × nv_pad floats (njmax_pad = round_up(njmax, 16)). Ch 9 §8, §9.

    7Reading contacts

    Pool, normal, rows

    • n = min(d.nacon.numpy()[0], d.naconmax), slice [:n], filter by contact.worldid.
    • geom[0] has the lower GeomType; frame[0] (the normal) points from geom[0] to geom[1] (Ch 9 §3).
    • contact.efc_address gives the first row; not every contact is a constraint: check the ContactType bits (Ch 9 §11).

    Contact forces from rows

    ids = wp.array(np.arange(n, dtype=np.int32))
f = wp.zeros(n, dtype=wp.spatial_vector)
mjw.contact_force(m, d, ids, False, f)   # to_world_frame=False: contact frame

    8Domain randomization

    Method 2: allocate, edit in place (graph friendly)

    m = mjw.put_model(mjm, batch_sizes={"geom_friction": nworld})
fr = m.geom_friction.numpy()                 # (nworld, ngeom, 3)
fr[:, :, 0] = np.linspace(0.1, 1.0, nworld)[:, None]
m.geom_friction.assign(fr)                   # same device array

    Keys must be top-level "*" Model fields; "opt.timestep", geom_type or nbody raise ValueError.

    Method 1: replace (the only way for m.opt)

    m.opt.gravity = wp.array(g_per_world, dtype=wp.vec3)  # (nworld,)
m.opt.timestep = wp.array(np.full(nworld, 0.002), dtype=float)
# replace BEFORE capturing a graph; after capture only assign

    Pitfall: unbatched derived outputs

    If you batch body_mass but not its derived outputs, set_const writes one shared row, computed from world 0 for most outputs; geom bounds are written by every world in a race. Batch the derived fields too, and keep set_const outside captured graphs (Ch 10 §7, §6).

    What may vary at all: numeric parameters yes; sizes, topology, types, discrete options and host flags no (Ch 10 §4). Contact materials mix per contact with friction = max (§10). Re-randomize on reset with an in-place kernel (§11).

    9Pitfalls

    • Reading after a reset without forward returns pre-reset xpos, sensors and contacts (Ch 8 §3).
    • reset_data zeroes ctrl: write actions after the reset.
    • Undersized state buffers: get_state does not check the size; allocate with mj_stateSize.
    • PHYSICS has no TIME: d.time keeps its value after a restore.
    • Overflow is silent physics: dropped contacts sink, dropped rows explode. The bits are sticky until reset_data.
    • nconmax is not a per-world guarantee: one busy world can starve the rest (Ch 9 §6).
    • Mass DR without set_const leaves invweight0/acc0 at the XML mass; changing an actuator gear from or to zero is unsafe (Ch 10 §6).
    • set_length_range overwrites unlimited actuators with (0, 0) and needs a per-world actuator_lengthrange (Ch 10 §8).
