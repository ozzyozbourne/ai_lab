Chapter 13

Observability and Debugging: Telemetry, Metrics, Tracing, Logs, gdb and Post-Mortem Analysis

A DPDK application owns its NIC, so the usual Linux tools (ip -s link, ethtool, tcpdump, top) show you almost nothing. This chapter gives you the replacements: ask the running process for numbers, record what it did, read its logs cheaply, stop it in a debugger, and open its corpse after a crash. It ends with five broken programs to fix, one table of every startup error seen so far, and the band 2 project.

1Why a DPDK app needs its own observability

With a kernel driver, the kernel is a witness. It counts every packet per interface, tcpdump can tap the stack, ethtool -S reads the NIC counters, and top tells you which process is busy. A DPDK application takes the NIC away from the kernel (ch1, ch9). The kernel no longer sees the packets, the interface may not even exist on the kernel side, and every polling lcore shows 100% CPU in top whether it moves 0 or 14 million packets per second. So the application itself has to answer the questions "how many?", "how busy?", "what happened, and when?" and "why did it crash?".

DPDK gives you a separate tool for each question. They differ in where they run and what they cost, and that decides when you use which:

2Telemetry: ask the running process

Telemetry (lib/telemetry) is a tiny server built into every DPDK process. It is on by default (--no-telemetry turns it off). During rte_eal_init() it creates a Unix socket in the process's runtime directory, /var/run/dpdk/<file-prefix>/dpdk_telemetry.v2 for root, and starts a control thread named dpdk-telemet-v2 that waits in accept(). Any program on the same machine with permission to open that file can connect and ask questions. Your lcores are not involved at all: they keep polling while the questions are answered on other threads.

The protocol in five rules

  1. The socket type is AF_UNIX, SOCK_SEQPACKET. Unlike a TCP-like stream, SEQPACKET keeps message boundaries: one send() is exactly one request, one recv() is exactly one reply.
  2. The server speaks first. On connect it sends {"version":"DPDK 26.11.0","pid":N,"max_output_len":16384}.
  3. A request is a command, optionally followed by a comma and a parameter string: /ethdev/stats,0. Everything after the first comma is passed to the callback as params.
  4. The reply is one JSON object whose single key is the command: {"/ethdev/stats": {...}}. An unknown command, or a callback that returns a negative value, gives {"/cmd": null}.
  5. Each connection gets its own pthread (at most 10 connections at once, MAX_CONNECTIONS in lib/telemetry/telemetry.c). A command name is shorter than 56 bytes, a reply is at most 16 KB.

The protocol is simple enough that a client fits in 25 lines. telclient.py connects, prints the hello message, and times each request:

code/telclient.pyPython
#!/usr/bin/env python3
# SPDX-License-Identifier: BSD-3-Clause
# Chapter 13: telclient.py - the whole telemetry protocol in 25 lines.
#
# usage: python3 -I telclient.py <file-prefix> <cmd> [<cmd> ...]
#
# The socket is <runtime dir>/dpdk_telemetry.v2, an AF_UNIX SOCK_SEQPACKET
# socket. SEQPACKET keeps message boundaries: one send() is one request,
# one recv() is one complete JSON reply (at most max_output_len bytes).
import json
import socket
import sys
import time

prefix = sys.argv[1]
path = f"/var/run/dpdk/{prefix}/dpdk_telemetry.v2"
s = socket.socket(socket.AF_UNIX, socket.SOCK_SEQPACKET)
s.connect(path)
hello = json.loads(s.recv(1024))            # server speaks first
print("connected to", path)
print("hello:", hello)
for cmd in sys.argv[2:]:
    t0 = time.perf_counter()
    s.send(cmd.encode())                    # "<command>[,<params>]"
    raw = s.recv(hello["max_output_len"])
    dt = (time.perf_counter() - t0) * 1e6
    reply = json.loads(raw)
    print(f"{cmd} -> {len(raw)} bytes in {dt:.0f} us")
    print("   ", json.dumps(reply)[:300])
s.close()

2.2 Your own endpoint

telemetry_app.c is a forwarder: a worker lcore moves packets between two net_null ports. It registers /ch13/stats, which returns its own counters as a JSON dictionary with one nested dictionary per port:

code/telemetry_app.c (the endpoint and the usage callback)C
/* ---- 1. the custom endpoint ------------------------------------------ */
/*
 * Runs on the telemetry thread ("dpdk-telemet-v2" spawns one pthread per
 * client connection), NOT on an lcore. It must only read shared state in a
 * thread-safe way, must be quick, and its JSON must fit in 16 KB.
 * Return 0 on success; a negative value makes the client see null.
 */
static int
tel_stats(const char *cmd __rte_unused, const char *params __rte_unused,
	  struct rte_tel_data *d)
{
	uint64_t hz = rte_get_tsc_hz();
	uint16_t p;

	rte_tel_data_start_dict(d);
	rte_tel_data_add_dict_uint(d, "worker_lcore", wctr.lcore);
	rte_tel_data_add_dict_uint(d, "uptime_ms",
		(rte_rdtsc() - wctr.start_tsc) * 1000 / hz);
	rte_tel_data_add_dict_uint(d, "busy_polls", get(&wctr.busy_polls));
	rte_tel_data_add_dict_uint(d, "idle_polls", get(&wctr.idle_polls));

	for (p = 0; p < 2; p++) {
		/* a nested container must be allocated and handed over;
		 * the library frees it after serialising (keep_data = 0) */
		struct rte_tel_data *pd = rte_tel_data_alloc();
		char name[16];

		if (pd == NULL)
			return -ENOMEM;
		rte_tel_data_start_dict(pd);
		rte_tel_data_add_dict_uint(pd, "rx", get(&pctr[p].rx));
		rte_tel_data_add_dict_uint(pd, "tx", get(&pctr[p].tx));
		rte_tel_data_add_dict_uint(pd, "drop", get(&pctr[p].drop));
		snprintf(name, sizeof(name), "port%u", p);
		rte_tel_data_add_dict_container(d, name, pd, 0);
	}
	return 0;
}

/* /ch13/echo,<anything>: the text after the first comma is 'params' */
static int
tel_echo(const char *cmd, const char *params, struct rte_tel_data *d)
{
	rte_tel_data_start_dict(d);
	rte_tel_data_add_dict_string(d, "cmd", cmd);
	rte_tel_data_add_dict_string(d, "params", params ? params : "(none)");
	return 0;
}

/* ---- 3. the lcore usage callback ------------------------------------- */
/*
 * Called by /eal/lcore/usage, /eal/lcore/info and rte_lcore_dump() for each
 * lcore, on whatever thread asked. Fill only what we know; return <0 for
 * lcores we do not track (they are then left out of the report).
 */
static int
usage_cb(unsigned int lcore_id, struct rte_lcore_usage *u)
{
	if (lcore_id != wctr.lcore || wctr.start_tsc == 0)
		return -1;
	u->total_cycles = rte_rdtsc() - wctr.start_tsc;
	u->busy_cycles = get(&wctr.busy_cycles);
	return 0;
}

Reading it from the top:

  • A callback has the type telemetry_cb: int (*)(const char *cmd, const char *params, struct rte_tel_data *d). It fills d; the library turns d into JSON. You never write JSON by hand.
  • First choose the shape: rte_tel_data_start_dict(d) for {"key": value}, rte_tel_data_start_array(d, RTE_TEL_UINT_VAL) for a list of one value type, or rte_tel_data_string(d, "text") for a single string.
  • Then add entries: rte_tel_data_add_dict_uint/int/string/uint_hex or the _array_ versions. A dictionary holds at most RTE_TEL_MAX_DICT_ENTRIES (256) entries, an array RTE_TEL_MAX_ARRAY_ENTRIES (512), a string value RTE_TEL_MAX_STRING_LEN (128) bytes.
  • Nesting: allocate a child with rte_tel_data_alloc(), fill it, and attach it with rte_tel_data_add_dict_container(d, name, child, 0). The last argument keep = 0 hands ownership to the library, which frees the child after serialising.
  • The callback runs on the connection's pthread, while the worker keeps writing the counters. So the counters are RTE_ATOMIC(uint64_t), written with a relaxed load+store by their one writer and read with relaxed loads (ch14 explains why plain uint64_t would be a data race). Never take a lock that an lcore holds for long, and keep the callback short.

2.3 The lcore usage callback

Every polling lcore looks 100% busy to the kernel, so only the application knows how much of its loop does real work. rte_lcore_register_usage_cb(cb) lets you tell EAL. When someone asks /eal/lcore/usage (or /eal/lcore/info,<id>), EAL calls cb(lcore_id, &usage) for each lcore; you fill usage->total_cycles and usage->busy_cycles (TSC cycles) and return 0, or return a negative value for lcores you do not track. What "busy" means is your decision. telemetry_app counts the cycles of loop iterations that moved packets; testpmd does the same when started with --record-core-cycles.

Read the source, not only the comment

The header says the usage callback is also used by rte_lcore_dump(). In 26.11, lcore_dump_cb() in lib/eal/common/eal_common_lcore.c does call it and builds the string ", busy cycles x/y (ratio z%)", then frees it without printing it. That is why the dump in the output above shows no usage. The telemetry endpoints work.

#
# The exporter imports every *.py in its load path. Each module provides
# info() (metric name -> (help text, type)) and metrics(sock), which queries
# telemetry and returns (name, value, labels) tuples. This one turns the
# app's own /ch13/stats endpoint into Prometheus metrics.
#

#        -s /var/run/dpdk/ch13-tel/dpdk_telemetry.v2 -o http://127.0.0.1:9913

PKTS = "port_packets"
POLLS = "worker_polls"


def info():
    return {
        PKTS: ("Packets counted by telemetry_app, by port and direction.", "counter"),
        POLLS: ("Worker loop iterations, busy or idle.", "counter"),
    }


def metrics(sock):
    st = sock.cmd("/ch13/stats")
    out = []
    for port in ("port0", "port1"):
        for d in ("rx", "tx", "drop"):
            out.append((PKTS, st[port][d], {"port": port, "dir": d}))
    out.append((POLLS, st["busy_polls"], {"kind": "busy"}))
    out.append((POLLS, st["idle_polls"], {"kind": "idle"}))
    return out

Tip: one connection, many questions

Every new connection costs the server a pthread_create(). A poller that reconnects every 100 ms makes the process create 10 threads per second forever. Keep one connection open and send many requests on it, as solutions/poll_pps.sh (exercise 2) does.

3Metrics, latency and bitrate

Three small libraries cooperate to answer "how long does a packet stay in my application?" and "how many bits per second?":

  • lib/metrics is a name → value table in a memzone (so secondary processes can read it). It has one row per port and one global row (RTE_METRICS_GLOBAL = -1). rte_metrics_init(socket) creates it; rte_metrics_reg_name(s) returns the key of a new name; rte_metrics_update_value(s)(port, key, ...) writes; rte_metrics_get_names() and rte_metrics_get_values(port, ...) read. Values are uint64_t.
  • lib/latencystats: rte_latencystats_init(samp_intvl_ns, NULL) adds an RX callback and a TX callback (ch12's burst callbacks) to every queue that exists at that moment. Every samp_intvl ns the RX callback marks one packet: it stores the TSC in the mbuf's dynamic timestamp field and sets the timestamp flag. When a marked packet goes through rte_eth_tx_burst(), the TX callback computes now - stamp and updates min, max, an average (EWMA with weight 1/4) and a jitter estimate (RFC 3550 style, weight 1/16). rte_latencystats_update() copies them, converted to ns, into the global metrics row.
  • lib/bitratestats: rte_stats_bitrate_calc(bd, port) reads rte_eth_stats_get(), computes the bits since the previous call, and writes mean_bits_in/out (last interval), peak_bits_in/out and ewma_bits_in/out (weight 20%) into the port's row. You call it on a fixed period, usually 1 s; the "per second" is your calling period.

static void
add_row(struct rte_tel_data *d, const char *row, int port,
	const struct rte_metric_name *names, int nnames)
{
	struct rte_metric_value vals[MAX_M];
	struct rte_tel_data *rd = rte_tel_data_alloc();
	int i, n;

	if (rd == NULL)
		return;
	rte_tel_data_start_dict(rd);

	for (i = 0; i < n; i++)
		if (vals[i].key < nnames && vals[i].value != 0)
			rte_tel_data_add_dict_uint(rd, names[vals[i].key].name,
						   vals[i].value);

	    struct rte_tel_data *d)
{

	int n = rte_metrics_get_names(names, MAX_M);
	uint16_t p;

		return n;

4Tracing: a flight recorder for events

Counters tell you how many. When you need what happened, in which order, and how long apart (a queue stopped, then a burst came back empty, then a reconfiguration started), you need a trace: a timestamped log of events, cheap enough to leave in the code. DPDK's trace library (in EAL: lib/eal/common/eal_common_trace*.c) writes binary events into a buffer per thread, with no locks, and saves them in the Common Trace Format (CTF), the format of LTTng that babeltrace and Trace Compass read.

4.1 Define, register, enable

A tracepoint is declared in a header with RTE_TRACE_POINT(name, RTE_TRACE_POINT_ARGS(...), emit list). The macro creates an inline function with your arguments that writes the listed fields with rte_trace_point_emit_u16(), _u32(), _u64(), _string(), _ptr() and friends:

/* SPDX-License-Identifier: BSD-3-Clause
 * Chapter 13: ch13_trace.h - the application's own tracepoints.
 *
 * RTE_TRACE_POINT() declares an inline function ch13_trace_port_cfg(...)
 * that writes the listed fields into this thread's trace buffer when the
 * tracepoint is enabled at run time (--trace=<regex>). When it is disabled
 * the cost is one load and one branch.
 *
 * RTE_TRACE_POINT_FP() is the fast-path flavour: its body is compiled to
 * nothing unless RTE_ENABLE_TRACE_FP is defined when THIS file is compiled
 * (meson -Denable_trace_fp=true defines it for the DPDK libraries; for your
 * own code a -DRTE_ENABLE_TRACE_FP on the compiler line is enough).
 *
 * Every tracepoint must be registered exactly once, in one .c file:
 * see ch13_trace_reg.c.
 */
#ifndef CH13_TRACE_H
#define CH13_TRACE_H

#include <rte_trace_point.h>

/* slow path: once per port configuration */
RTE_TRACE_POINT(
	ch13_trace_port_cfg,
	RTE_TRACE_POINT_ARGS(uint16_t port, uint16_t nb_desc, const char *drv),
	rte_trace_point_emit_u16(port);
	rte_trace_point_emit_u16(nb_desc);
	rte_trace_point_emit_string(drv);
)

/* fast path: once per RX burst */
RTE_TRACE_POINT_FP(
	ch13_trace_burst,
	RTE_TRACE_POINT_ARGS(uint16_t port, uint16_t nb_rx),
	rte_trace_point_emit_u16(port);

)

#endif
/* SPDX-License-Identifier: BSD-3-Clause
 * Chapter 13: ch13_trace_reg.c - the ONE translation unit that registers
 * the tracepoints. rte_trace_point_register.h must come BEFORE the header
 * that defines them: it switches RTE_TRACE_POINT() from "declare an inline
 * emitter" to "emit the field descriptions for the CTF metadata".
 * RTE_TRACE_POINT_REGISTER(object, name) gives each one the name that
 * --trace=<regex> matches (here "ch13.port_cfg" and "ch13.burst").

 * rte_build_config.h (pulled in by rte_config.h, which every DPDK header

 * second #undef), THEN define the macro. Build with:
 *     gcc -include trace_fp_on.h ...

#include <rte_config.h>
#define RTE_ENABLE_TRACE_FP 1

Three rules that cost people hours:

  1. Register exactly once. One .c file includes rte_trace_point_register.h before the tracepoint header and lists RTE_TRACE_POINT_REGISTER(object, name). The name (ch13.port_cfg) is what --trace matches and what the CTF metadata shows.
  2. Nothing is recorded until you enable it. --trace=<regex> (repeatable) enables the matching tracepoints at startup; rte_trace_regexp(), rte_trace_pattern(), rte_trace_point_enable/disable() do it at run time. --trace-dir chooses where files go (default: $HOME/dpdk-traces/), --trace-bufsz the size of each thread's buffer (default 1 MB), --trace-mode=o|d what happens when it is full: overwrite the oldest events (the default) or discard new ones.
  3. Fast-path tracepoints are compiled out by default. RTE_TRACE_POINT_FP only emits if RTE_ENABLE_TRACE_FP is defined. DPDK built without -Denable_trace_fp=true installs an rte_build_config.h that says #undef RTE_ENABLE_TRACE_FP, which also cancels a -DRTE_ENABLE_TRACE_FP on your command line. trace_fp_on.h is the workaround for your own code: include rte_config.h first, then define the macro, and build with -include trace_fp_on.h.

The trace API is still experimental in 26.11, so these files need -DALLOW_EXPERIMENTAL_API. To emit a generic EAL event without defining your own, include rte_eal_trace.h and call rte_eal_trace_generic_str("..."), _u64(), and so on.

5Logs in the fast path

You met rte_log in ch3: every message has a log type (a name such as lib.eal, pmd.net.tap or your own user.ch13) and a level from EMERG (1) to DEBUG (8). --log-level=<pattern>:<level> sets the level per type with wildcards (--log-level='pmd.net.*:debug'), --log-timestamp[=delta|reltime|iso|ctime] adds timestamps, --syslog[=facility] sends everything to syslog (and so to journald on a systemd host). A message prints only if its level is at or above the type's current level, and that check happens at run time, on every call.

A run-time check is cheap, but not free, and the format string and the call stay in your binary. For per-packet messages use RTE_LOG_DP(level, type, ...). It adds a compile-time test against RTE_LOG_DP_LEVEL, which config/rte_config.h sets to RTE_LOG_INFO. A DEBUG data-path message is then a constant-false branch: the compiler deletes it, and no --log-level can bring it back.

7Debugging a live process: gdb, rte_panic, ASan, mbuf checks

7.1 gdb on a DPDK application

gdb works on DPDK programs like on any other: gdb --args ./app <EAL args> -- <app args>. Three things are specific:

  • Threads have names. Each worker lcore is a pthread called dpdk-worker<N>; EAL adds dpdk-intr (interrupts, alarms, LSC callbacks), dpdk-mp-msg (multi-process IPC, ch16) and dpdk-telemet-v2. info threads and thread apply all bt show who is where.
  • The burst functions are inline. rte_eth_rx_burst() is a static inline in rte_ethdev.h that calls through rte_eth_fp_ops[port].rx_pkt_burst. You cannot break on rte_eth_rx_burst; break on the driver function instead (eth_null_rx, pmd_rx_burst for tap, eth_ring_rx). p rte_eth_fp_ops[0].rx_pkt_burst tells you its name.
  • DPDK itself has no debug info here. The installed libraries are a release build, so their internal structs (like the null PMD's queue) are unknown to gdb. Public structs that your -g code includes (struct rte_mbuf, struct rte_mempool) are fully known. Functions of the library can be called from gdb, but you must cast the return type. For full debug info rebuild DPDK with meson -Dbuildtype=debug (or debugoptimized).

panic_demo.c polls a net_null port on lcore 1, builds a healthy mbuf with a marker payload, then corrupts it (data_len = 4000 in a 2176-byte buffer), asks rte_mbuf_check() what is wrong and calls rte_panic():

rte_panic, rte_exit, and signals

rte_panic(fmt, ...) prints PANIC in <function>(), the message and a stack dump, then calls abort(): you get SIGABRT and a core file. rte_exit(code, fmt, ...) prints the message, runs rte_eal_cleanup() and exits cleanly: no core. Use rte_exit for "bad configuration", rte_panic for "this cannot happen, keep the evidence". EAL installs no SIGSEGV handler, so a segfault produces a core file directly (if allowed: section 8). rte_dump_stack() alone is handy in your own error paths.

7.2 AddressSanitizer

ASan instruments every memory access of the code it compiles and reports the first out-of-bounds or use-after-free access, with the stack of the access and of the allocation. Building your application with gcc -fsanitize=address -fno-omit-frame-pointer works against the normal static DPDK. What it can see:

  • yes: malloc/free, the stack and globals of your code;
  • no: rte_malloc memory, memzones and mempool objects (mbufs). DPDK can teach ASan about its own heap, but only when DPDK itself is built with meson -Db_sanitize=address (doc/guides/prog_guide/asan.rst). Even then, mempool objects are not poisoned on free, so ASan does not see an mbuf double free (lab 4).

7.3 Checking mbufs

  • rte_mbuf_check(m, is_header, &reason) returns 0 or -1 and a reason string: pool NULL, bad IOVA, bad virtual address, refcnt 0 or 0xffff, and for a packet header data_len > pkt_len, a segment that overruns its buffer, a wrong nb_segs or pkt_len. rte_mbuf_sanity_check(m, is_header) does the same and calls rte_panic on failure. Both are normal functions, available in every build.
  • Compiling your code with -DRTE_LIBRTE_MBUF_DEBUG turns on the checks hidden inside the inline mbuf functions (__rte_mbuf_sanity_check in rte_pktmbuf_free, rte_mbuf_raw_alloc, ...). The libraries keep whatever they were built with.
  • rte_pktmbuf_dump(stdout, m, len) prints the header fields and a hex dump of the data.
  • Pool-level checks need a DPDK build option: RTE_LIBRTE_MEMPOOL_DEBUG adds cookies around every object and catches a double free on the second put. 26.11 also has mbuf history (lib/mbuf/rte_mbuf_history.h): with RTE_MBUF_HISTORY_DEBUG every mbuf records its last 16 operations (alloc, RX, TX, free by PMD/app, ...), dumped with rte_mbuf_history_dump_all() and decoded by usertools/dpdk-mbuf-history-parser.py. Neither option is enabled in this course build (config/rte_config.h: "is not set").
  • rte_mempool_in_use_count() and rte_mempool_avail_count() (or telemetry /mempool/info) are the leak detector you always have: at a quiet moment, in-use must equal what you know you hold.

8Post-mortem: core dumps that contain the packets

A production process that crashed at 3 a.m. cannot be stepped through. What you get is a core file: a snapshot of the process's memory and registers at the moment it died, which gdb opens like a stopped process (gdb ./app core). Three settings decide whether you get one and what is in it:

  1. ulimit -c, the core size limit of the process. It is often 0 (no core at all). Set it with ulimit -c unlimited in the shell that starts the program, or LimitCORE=infinity in a systemd unit (ch29).
  2. /proc/sys/kernel/core_pattern, where the core goes. A plain name (core, as on this VM) writes into the process's current directory. On most distributions it is a pipe to systemd-coredump; then you list and open cores with coredumpctl list and coredumpctl gdb. Disk limits for systemd-coredump are in /etc/systemd/coredump.conf.
  3. /proc/<pid>/coredump_filter, a bit mask that decides which kinds of mappings are written (man 5 core). It is inherited across fork() and exec(), so you set it in the parent shell: echo 0x73 > /proc/self/coredump_filter, then start the program.

/* SPDX-License-Identifier: BSD-3-Clause
 * Chapter 13 debug lab 2: mtu_noscatter - "big packets arrive broken".
 *
 * Story: the network now carries 9000-byte jumbo frames. Our port was left
 * at the default MTU (1500), the mbuf pool has the default 2 KB data room
 * (RTE_MBUF_DEFAULT_BUF_SIZE) and the SCATTER RX offload is off, so one

 * tap interface whose MTU we raise to 9000 (that is "the wire").

 * ("MTU 9000 requires 5 scatter segments, but offload not set") and

 * Story: a filter was added to the forwarder: only IPv4 is forwarded, the
 * rest is dropped. The drop branch does "continue" and forgets to free the

/* SPDX-License-Identifier: BSD-3-Clause
 * Chapter 13 debug lab 4: double_free - "random packets carry the wrong data".
 *
 * Story: an error path frees a bad packet and then jumps to the common
 * cleanup label, which frees it again. A freed mbuf keeps refcnt 1 and
 * looks perfectly valid, so rte_mbuf_sanity_check() and rte_mbuf_check()
 * say nothing, and a release build of DPDK has no mempool cookies. The
 * second free puts the SAME pointer into the pool twice: later two
 * rte_pktmbuf_alloc() calls return the same buffer, and two "different"
 * packets overwrite each other.
 *
 * 200 mbufs are "posted to the NIC RX ring" (held) while the loop runs,
 * so the pool is never full and the duplicate pointers fit into it.
 * When those 200 come back at the end, the pool's ring (capacity = size)
 * has no room for all of them: a release build silently ignores the failed
 * bulk enqueue, and a whole bulk of real mbufs is lost. So a double free is
 * also a leak, and in_use_count lies in both directions.
 *
 * How to see it anyway:
 *   - an audit: take all 'size' objects out of the pool and sort the
 *     pointers: duplicates show up next to each other.
 *   - telemetry /mempool/info,lab_pool: compare common_pool_count with the
 *     number of objects you believe are free.
 *   - a DPDK build with RTE_LIBRTE_MEMPOOL_DEBUG checks object cookies on
 *     every put and panics on the second one (not available in this build).
 * Build with -DFIXED: free in exactly one place (the cleanup label).
 *
 *   ./lab -l 0 --no-pci --no-huge -m 128 --file-prefix=ch13-dbg-dfree
 */
#include "../../ch13_common.h"

#define POOL 511

static int
cmp_ptr(const void *a, const void *b)
{
	uintptr_t x = *(const uintptr_t *)a, y = *(const uintptr_t *)b;

	return x < y ? -1 : x > y;
}

{
	(void)m;
	if (i % 100 == 7) {             /* every 100th packet is "malformed" */
#ifndef FIXED
		rte_pktmbuf_free(m);    /* BUG: the error path frees ...    */
#endif
		return -1;
	}
	return 0;
}

{
	static void *objs[POOL];
	static struct rte_mbuf *posted[200];
	struct rte_mempool *mp;
	unsigned int i, bad = 0, dups = 0;
	const char *reason __rte_unused = NULL;
	unsigned int avail;

	if (rte_eal_init(argc, argv) < 0)
		rte_exit(EXIT_FAILURE, "EAL init failed\n");

			break;

		if (handle(m, i) < 0) {

		}
cleanup:

	}

/* SPDX-License-Identifier: BSD-3-Clause
 * Chapter 13 debug lab 5: two_lcores_one_queue - "counters do not add up".
 *
 * Story: to "use more cores", the same forwarding function was launched on
 * two lcores, and both poll port 0 queue 0 (and transmit on it). An ethdev
 * queue is single-threaded: the PMD keeps per-queue state without locks.
 * net_ring's queue is an rte_ring created single-producer/single-consumer
 * (RING_F_SP_ENQ | RING_F_SC_DEQ), so two consumers can dequeue the SAME
 * mbufs, and two producers can overwrite each other's slots. Packets get
 * duplicated or lost, and the PMD's plain (non-atomic) counters lose
 * updates.
 *
 * The check: 256 frames are injected into a loopback port; after the run,
 * drain the port and count what is left. Without the bug exactly 256
 * distinct mbufs come back and in_use is 256 before the drain, 0 after.
 * Build with -DFIXED: each lcore owns one port (queue) of its own.
 *
 *   ./lab -l 0-2 --no-pci --no-huge -m 128 --file-prefix=ch13-dbg-2lc \
 *       --vdev=net_ring0 --vdev=net_ring1
 */
#include "../../ch13_common.h"

static RTE_ATOMIC(uint64_t) app_rx[RTE_MAX_LCORE];

static int
fwd(void *arg)
{
	uint16_t port = (uint16_t)(uintptr_t)arg;
	struct rte_mbuf *pkts[32];
	uint64_t n_rx = 0;

	while (!ch13_quit) {
		uint16_t n = rte_eth_rx_burst(port, 0, pkts, 32), s;

		n_rx += n;
		s = rte_eth_tx_burst(port, 0, pkts, n);  /* loop back */
		if (s < n)
			rte_pktmbuf_free_bulk(&pkts[s], n - s);
	}
	rte_atomic_store_explicit(&app_rx[rte_lcore_id()], n_rx,
				  rte_memory_order_relaxed);
	return 0;
}

What the labs teach beyond the fix
  • promisc_off: a port's receive filter drops frames for addresses it was not told about. /ethdev/info shows promiscuous: 0 and /ethdev/macs lists the only accepted unicast address. rte_eth_dev_mac_addr_add() is the targeted fix; promiscuous mode is the blunt one.
  • mtu_noscatter: the drop is counted in ierrors, not in imissed; the program's own counters only see "nothing arrived". With rxmode.mtu = 9000 but no SCATTER flag, net_tap only warns and scatters anyway; do not rely on that on real NICs.
  • leak: once the pool is empty the PMD cannot refill, and RX simply returns 0. net_null does not count rx_nombuf; a real NIC PMD does. The telemetry signature is common_pool_count stuck near 0 and ipackets frozen.
  • double_free: invisible to rte_mbuf_check() (a freed mbuf keeps refcnt = 1) and to ASan. The signature is an in_use count lower than what you hold (190 instead of 200), later a pool that is short of mbufs, and duplicate pointers in an audit. A double free is also a leak: the extra put fills the ring and a later bulk put is dropped silently.
  • two_lcores_one_queue: the result changes from run to run (sometimes 0 mbufs come back, sometimes 4096 with thousands of duplicates). Non-reproducible counts that do not add up are the classic sign of a data race; ch14 explains why, ch15 shows the right way to use more cores (one queue per lcore with RSS).

/* SPDX-License-Identifier: BSD-3-Clause
 * Chapter 13, band 2 project (solution): a multi-core L2 forwarder that you
 * can watch and check.
 *
 * It is chapter 11's evolving app grown to two forwarding lcores, with the
 * observability of this chapter built in:
 *
 *   lcore 0 (main)   control plane: rte_timer report every 500 ms, a
 *                    cmdline shell read from stdin without blocking
 *                    (cmdline_in), and the end-of-test check
 *   lcore 1          forwards port 0 <-> port 1   (net_ring0, net_ring1)
 *   lcore 2          forwards port 2 <-> port 3   (net_ring2, net_ring3)
 *   telemetry        /band2/stats: per-lcore rx/tx/drop + pool in_use
 *
 * Every net_ring port is a loopback, so a frame sent on port 1 comes back
 * on port 1 and is forwarded to port 0, and so on: the frames of a pair
 * circulate between its two ports. To make the test finite and exact,
 * each frame carries a hop budget (32 bits in the UDP payload). Every
 * receive decrements it; at 0 the frame is dropped ("TTL expired").
 * With N frames per pair and a budget of H hops the counters MUST end at
 *     rx = N*H,  drop = N,  tx = rx - drop   for each lcore,
 * and the mempool must be full again (in_use = 0).
 *
 *   ./l2fwd_mc -l 0-2 --no-pci --no-huge -m 128 --file-prefix=ch13-b2 \
 *       --vdev=net_ring0 --vdev=net_ring1 --vdev=net_ring2 --vdev=net_ring3 \
 *       -- [--frames N] [--hops H]  < commands
 */

/* ---- per-lcore statistics ---------------------------------------------
 * One writer per entry (its lcore), readers on lcore 0 and the telemetry
 * thread. Each entry is alone in its cache line(s): no false sharing
 * between the two forwarding lcores (chapter 14 shows the cost if not). */
struct __rte_cache_aligned lcore_stats {
	RTE_ATOMIC(uint64_t) rx;
	RTE_ATOMIC(uint64_t) tx;
	RTE_ATOMIC(uint64_t) drop;
	uint16_t port_a, port_b;       /* the pair this lcore owns */
	bool used;
};
static struct lcore_stats lstats[RTE_MAX_LCORE];

static struct rte_mempool *pool;
static unsigned int frames = 512;
static uint32_t hops = 200000;
static volatile bool stop_fwd, shell_done;
static struct rte_timer report_tim;

static inline void
st_add(RTE_ATOMIC(uint64_t) *c, uint64_t n)
{
	rte_atomic_store_explicit(c,
		rte_atomic_load_explicit(c, rte_memory_order_relaxed) + n,
		rte_memory_order_relaxed);
}
#define ST(lc, f) rte_atomic_load_explicit(&lstats[lc].f, rte_memory_order_relaxed)

/* the hop budget lives right after the UDP header */
static inline uint32_t *
hop_field(struct rte_mbuf *m)
{
	return rte_pktmbuf_mtod_offset(m, uint32_t *,
		sizeof(struct rte_ether_hdr) + sizeof(struct rte_ipv4_hdr) +
		sizeof(struct rte_udp_hdr));
}

/* ---- the data plane ---------------------------------------------------- */
static void
fwd_one(struct lcore_stats *s, uint16_t in, uint16_t out)
{
	struct rte_mbuf *pkts[BURST], *keep[BURST];
	uint16_t n = rte_eth_rx_burst(in, 0, pkts, BURST), i, k = 0, sent;
	uint64_t dropped = 0;

	if (n == 0)
		return;
	for (i = 0; i < n; i++) {
		uint32_t *h = hop_field(pkts[i]);

		if (--*h == 0) {                   /* budget used up */
			rte_pktmbuf_free(pkts[i]);
			dropped++;
			continue;
		}
		/* l2fwd-style MAC rewrite: src = our port, dst = next hop */
		struct rte_ether_hdr *eh = rte_pktmbuf_mtod(pkts[i], struct rte_ether_hdr *);
		eh->src_addr.addr_bytes[5] = (uint8_t)out;
		keep[k++] = pkts[i];
	}
	sent = rte_eth_tx_burst(out, 0, keep, k);
	if (sent < k) {                            /* TX ring full */
		rte_pktmbuf_free_bulk(&keep[sent], k - sent);
		dropped += k - sent;
	}
	st_add(&s->rx, n);
	st_add(&s->tx, sent);
	st_add(&s->drop, dropped);
}

static int
fwd_main(void *arg __rte_unused)
{
	struct lcore_stats *s = &lstats[rte_lcore_id()];

	while (!stop_fwd) {
		fwd_one(s, s->port_a, s->port_b);
		fwd_one(s, s->port_b, s->port_a);
	}
	return 0;
}

/* ---- observability: report, telemetry, shell ------------------------- */
static void
print_stats(FILE *f)
{
	unsigned int lc;

	fprintf(f, "  t=%.2fs in_use=%u", (double)(rte_rdtsc() - t_start) / rte_get_tsc_hz(),
		rte_mempool_in_use_count(pool));
	RTE_LCORE_FOREACH_WORKER(lc)
		if (lstats[lc].used)
			fprintf(f, " | lcore%u p%u<->p%u rx=%" PRIu64 " tx=%" PRIu64 " drop=%" PRIu64,
				lc, lstats[lc].port_a, lstats[lc].port_b,
				ST(lc, rx), ST(lc, tx), ST(lc, drop));
	fprintf(f, "\n");
}

report_cb(struct rte_timer *t __rte_unused, void *arg __rte_unused)

	TOKEN_STRING_INITIALIZER(struct cmd_res, w2, "stats#pool");
static cmdline_parse_inst_t cmd_show = {
	.f = cmd_show_cb, .help_str = "show stats|pool",
	.tokens = { (void *)&t_show, (void *)&t_what, NULL },
};

static void
cmd_quit_cb(void *parsed __rte_unused, struct cmdline *cl, void *d __rte_unused)
{
	(void)cl;
	printf("[shell] quit: waiting for the traffic to drain\n");
	fflush(stdout);
	shell_done = true;
}
static cmdline_parse_token_string_t t_quit =
	TOKEN_STRING_INITIALIZER(struct cmd_res, w1, "quit");
static cmdline_parse_inst_t cmd_quit = {
	.f = cmd_quit_cb, .help_str = "quit",
	.tokens = { (void *)&t_quit, NULL },
};
static cmdline_parse_ctx_t ctx[] = {
	(cmdline_parse_inst_t *)&cmd_show, (cmdline_parse_inst_t *)&cmd_quit, NULL
};

/* feed whatever stdin has into the shell, without blocking */
static void
shell_poll(struct cmdline *cl)
{
	struct pollfd pfd = { .fd = 0, .events = POLLIN };
	char buf[128];
	ssize_t n;

	if (shell_done || poll(&pfd, 1, 0) <= 0)
		return;
	n = read(0, buf, sizeof(buf));
	if (n <= 0) {
		shell_done = true;            /* EOF counts as quit */
		return;
	}
	cmdline_in(cl, buf, n);
}

/* ---- setup ------------------------------------------------------------- */
static void
inject(uint16_t port, unsigned int n)
{
	unsigned int i;

	for (i = 0; i < n; i++) {
		struct rte_mbuf *m = rte_pktmbuf_alloc(pool);

		if (m == NULL || ch13_make_udp(m, 64, i) < 0)
			rte_exit(EXIT_FAILURE, "inject: no mbuf\n");
		*hop_field(m) = hops;
		if (rte_eth_tx_burst(port, 0, &m, 1) != 1)
			rte_exit(EXIT_FAILURE, "inject: ring full\n");
	}
}

int
main(int argc, char **argv)
{
	static const struct option lo[] = {
		{"frames", required_argument, NULL, 'f'},
		{"hops", required_argument, NULL, 'h'},
		{NULL, 0, NULL, 0}
	};
	struct cmdline *cl;
	unsigned int lc, k = 0, fail = 0;
	uint64_t deadline;
	uint16_t p;
	int ret, c;

	ret = rte_eal_init(argc, argv);
	if (ret < 0)
		rte_exit(EXIT_FAILURE, "EAL init failed\n");
	argc -= ret;
	argv += ret;
	while ((c = getopt_long(argc, argv, "", lo, NULL)) != -1) {
		if (c == 'f')
			frames = atoi(optarg);
		else if (c == 'h')
			hops = strtoul(optarg, NULL, 0);
	}
	ch13_signals();
	if (rte_eth_dev_count_avail() != NB_PORTS || rte_lcore_count() != 3)
		rte_exit(EXIT_FAILURE, "need -l 0-2 and 4 net_ring ports\n");
	if (frames == 0 || frames > 1000 || hops == 0)
		rte_exit(EXIT_FAILURE, "--frames 1..1000, --hops >= 1\n");

	pool = rte_pktmbuf_pool_create("band2_pool", 4095, 64, 0,
				       RTE_MBUF_DEFAULT_BUF_SIZE, rte_socket_id());
	if (pool == NULL)
		rte_exit(EXIT_FAILURE, "pool: %s\n", rte_strerror(rte_errno));
	for (p = 0; p < NB_PORTS; p++)
		if (ch13_port_init(p, pool, NULL, 1024) < 0)
			rte_exit(EXIT_FAILURE, "port %u init failed\n", p);

	RTE_LCORE_FOREACH_WORKER(lc) {             /* lcore 1: 0,1  lcore 2: 2,3 */
		lstats[lc].port_a = 2 * k;
		lstats[lc].port_b = 2 * k + 1;
		lstats[lc].used = true;
		inject(2 * k, frames);
		k++;
	}
	printf("%u frames per pair, hop budget %u: expect per lcore rx=%" PRIu64
	       " tx=%" PRIu64 " drop=%u\n", frames, hops,
	       (uint64_t)frames * hops, (uint64_t)frames * hops - frames, frames);

	rte_telemetry_register_cmd("/band2/stats", tel_band2,
		"Band 2 forwarder: per-lcore rx/tx/drop and pool in_use");
	rte_timer_subsystem_init();
	rte_timer_init(&report_tim);
	rte_timer_reset(&report_tim, rte_get_timer_hz() / 2, PERIODICAL,
			rte_lcore_id(), report_cb, NULL);
	cl = cmdline_new(ctx, "", 0, 1);
	if (cl == NULL)
		rte_exit(EXIT_FAILURE, "cmdline_new failed\n");

	t_start = rte_rdtsc();
	RTE_LCORE_FOREACH_WORKER(lc)
		rte_eal_remote_launch(fwd_main, NULL, lc);
	printf("READY\n");
	fflush(stdout);

	/* control loop: timers, shell, and "is all traffic gone?" */
	deadline = rte_rdtsc() + 12 * rte_get_tsc_hz();
	while (!ch13_quit && rte_rdtsc() < deadline) {
		rte_timer_manage();
		shell_poll(cl);
		if (shell_done && rte_mempool_in_use_count(pool) == 0)
			break;
		rte_delay_us_sleep(1000);
	}
	stop_fwd = true;
	rte_eal_mp_wait_lcore();
	rte_timer_stop_sync(&report_tim);
	cmdline_free(cl);

	/* ---- acceptance check ------------------------------------------- */
	printf("final:");
	print_stats(stdout);
	RTE_LCORE_FOREACH_WORKER(lc) {
		uint64_t rx = ST(lc, rx), tx = ST(lc, tx), dr = ST(lc, drop);
		bool ok = rx == tx + dr && rx == (uint64_t)frames * hops && dr == frames;

		printf("check lcore%u: rx == tx + drop (%" PRIu64 " == %" PRIu64 "), "
		       "rx == frames*hops, drop == frames: %s\n",
		       lc, rx, tx + dr, ok ? "ok" : "WRONG");
		fail += !ok;
	}
	printf("check mempool in_use == 0: %u -> %s\n", rte_mempool_in_use_count(pool),
	       rte_mempool_in_use_count(pool) == 0 ? "ok" : "WRONG");
	fail += rte_mempool_in_use_count(pool) != 0;
	printf("RESULT: %s\n", fail ? "FAIL" : "PASS");

	for (p = 0; p < NB_PORTS; p++) {
		rte_eth_dev_stop(p);
		rte_eth_dev_close(p);
	}
	rte_timer_subsystem_finalize();
	rte_eal_cleanup();
	return fail ? 1 : 0;
}

Common pitfalls

  • "Error connecting to .../dpdk_telemetry.v2": wrong --file-prefix (the client's -f must match), the app runs with --no-telemetry, or the client runs as a user who cannot open the root runtime dir. dpdk-telemetry.py -l lists prefixes, including those of dead processes.
  • An endpoint silently missing: rte_telemetry_register_cmd() returned -EINVAL because of a - or . in the name, a missing leading /, a name of 56+ bytes or help text of 128+ bytes. Check the return value.
  • A telemetry callback that takes a lock held by an lcore: the client hangs and, worse, the lcore may stall if it waits for the callback. Read counters with relaxed atomics; never block in a callback.
  • Reply truncated or null: the JSON must fit in 16 KB, a dict in 256 entries, an array in 512. Split big answers by parameter (/x/info,<id>).
  • /eal/lcore/usage is empty: nobody registered rte_lcore_register_usage_cb() (testpmd: --record-core-cycles).
  • latencystats numbers that grow with uptime: mbufs are recycled without passing through a fresh RX (loopbacks, reassembly, in-place replies). Call rte_latencystats_init() after the queues are set up; queues created later have no callbacks.
  • Using the removed rte_metrics_tel_* API from an older tutorial: it is gone in 26.11; write your own endpoint (section 3).
  • Empty trace: no --trace regex (nothing is enabled by default), a regex typo (only logged), a fast-path tracepoint without RTE_ENABLE_TRACE_FP, or a --trace-dir whose parent does not exist (error only at save time).
  • Link error "undefined reference to __rte_trace_point_emit_field" or deprecation warnings: missing -DALLOW_EXPERIMENTAL_API; for generic tracepoints also #include <rte_eal_trace.h>.
  • RTE_LOG(DEBUG) in the per-packet path: ~10 extra cycles per call even when disabled (measured above). Use RTE_LOG_DP.
  • gdb "Function rte_eth_rx_burst not defined": it is inline. Break on the PMD's burst function (p rte_eth_fp_ops[0].rx_pkt_burst gives the name). Cast return types when calling DPDK functions from gdb.
  • A core with zeroed mbufs, or no core: coredump_filter lacks bit 6, ulimit -c is 0, or core_pattern pipes to systemd-coredump (look with coredumpctl). Test your crash procedure with hugepages, not only with --no-huge.
  • Believing ASan or rte_mbuf_check() found nothing, so there is no mbuf bug: neither sees a double free of a mempool object in this build. Audit counts.

Summary
  • Telemetry is a JSON-over-SEQPACKET server in every DPDK process: one hello, command[,params] requests, replies of at most 16 KB, a pthread per client. Add endpoints with rte_telemetry_register_cmd() and rte_tel_data_*; read shared counters with relaxed atomics.
  • rte_lcore_register_usage_cb() makes /eal/lcore/usage meaningful; dpdk-telemetry-exporter.py with your own endpoint module brings it all to Prometheus.
  • latencystats measures time between the RX and TX callbacks of sampled packets; bitratestats turns ethdev byte counters into bits per calling period; lib/metrics stores both. In 26.11 you expose the table with your own endpoint.
  • Tracepoints: declare with RTE_TRACE_POINT, register once, enable with --trace; fast-path ones need RTE_ENABLE_TRACE_FP at compile time. Output is CTF: TSDL metadata plus one binary channel per thread.
  • RTE_LOG_DP below RTE_LOG_DP_LEVEL costs nothing; RTE_LOG always costs a call.
  • gdb: break on PMD burst functions, not the inline wrappers; rte_panic leaves a backtrace and a core; ASan and rte_mbuf_check() catch some bugs but not mempool double frees.
  • Without bit 6 in coredump_filter a hugepage DPDK core has no mbufs, and gdb shows zeros instead of errors. Use 0x73 or 0x7f in production.
  • Counters that do not add up, pools that do not refill, and frames counted in the wrong error counter diagnose most data-path bugs before you open a debugger.
