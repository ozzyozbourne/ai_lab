Why do databases use B-trees instead of a sorted array or a binary search tree? Because the cost that matters is the number of pages read, not the number of comparisons. Three figures: a race, a calculator, and the price of an insert. Text and code: chapter 01 README.

1. The race: one lookup, three structures

The same keys are stored three ways. Every structure lives on pages of the same size: a page of the sorted array holds a few keys, a binary-search-tree node is a page with one key, a wide node is a page full of keys. Each step is one page read for every structure that is still searching. Comparisons inside a page that has already been read are free.

2. Fan-out and height

A node with M children divides the remaining keys by M. Move the sliders and watch how few levels a wide tree needs, and how little it matters whether the nodes are full or only half full.

3. The price of a put into one flat array

Reading a sorted array is cheap. Changing it is not: every entry behind the new key moves, and every page they sit on is rewritten.
