    A Tour of the mujoco_warp Repository

    What lives where in google-deepmind/mujoco_warp at commit 8f5b9f1: the package that pip installs, and the benchmarks, contrib tools and notebooks that only the git repository has. Every module links to the chapter that reads it.

    Line counts: wc -l at 8f5b9f137 engine modules·79,064 source lines, 57,773 test lines

    On this page

    • The top-level layout, and which parts the 4.0.1 wheel ships.
    • A treemap and table of every _src module: size, job, tests, owning chapter.
    • The CLI scripts, test data, benchmark suite, contrib/ and the notebook.

    1The layout in one picture

    The repository has two halves. mujoco_warp/ is the Python package; pip install mujoco-warp ships it (the wheel also carries test_data/). Everything else (benchmarks/, contrib/, notebooks/, CI) exists only in git, so code that needs it must clone the repo (Ch 28 §6 shows what breaks when you forget).

    Version note: dev tree vs 4.0.1

    The chapters pin the 4.0.1 wheel. The tree at 8f5b9f1 is a little newer: it adds _src/sort.py (canonical contact and constraint order, Ch 22 §2) and _src/render_optix.py (OptiX back end, Ch 27 §13), extends types.py (for example PID actuator types) and rewrites viewer.py on MuJoCo Studio (Ch 5 §9). The public names in __init__.py are identical.

    2The front door: mujoco_warp/__init__.py

    134 lines. It sets __version__ from the installed metadata, imports every public name from _src with an explicit as (step, Model and Data first, under # isort: off), and ends with _differentiable(locals()), which wraps the public functions for the experimental gradient API (Ch 29 §3). Everything under _src is private: the course marks such imports with a private API badge. The full list, with signatures, is API at a glance.

    6The benchmark suite: benchmarks/

    Repo only. Each subfolder with an __init__.py defines a BENCHMARKS list (and optionally pinned ASSETS such as MuJoCo Menagerie); every key except name, mjcf and assets becomes a mjwarp-testspeed flag. Full table of benchmarks and flags: Ch 25 §6.

    FileLinesWhat it does
    run.py212Discover benchmarks (-f/--filter regex), fetch assets, run testspeed with --format=short, the trace, memory and solver reports; --view opens one in the viewer.
    sweep.py306Run every benchmark across a range of commits (forward/back, --daily, --mock) and write nightly/*.jsonl to the gh-pages branch.
    common.py85Command and asset helpers shared by run.py and sweep.py.
    kitchen/populate_scene.py156Place a Menagerie robot in the kitchen scene. kitchen/ has no __init__.py, so run.py does not discover it.

    Benchmark folders with an __init__.py: aloha, cloth, franka_emika_panda, franka_threading, humanoid, myosim, render, sharpa_wave, unitree_g1. Without: kitchen.

    7Experiments and tools: contrib/

    Repo only. The README calls it "a home for experiments, helper scripts and other tools that are not officially part of MJWarp", subject to change with no notice.

    contrib/render.py · 531 lines

    CLI renderer

    RGB/depth images, PLY Gaussian splats, --tiled, --rollout, --orbit. Its docstring says mjwarp-render, but pip does not install it. Pitfall: it passes create_render_context arguments by position, so --shadows toggles fast math instead (Ch 27 §5).

     contrib/jax_unroll.py · 85 lines

    JAX bridge benchmark

    8192 humanoids through jax_callable. Stale: wrong benchmark path, nconmax read as a total (now per world), wp.clear_kernel_cache() at import, hard-coded 8192.

     contrib/kernel_analyzer/

    Kernel analyzer

    An ast-based checker for MJWarp's kernel conventions (parameter grouping, _in/_out suffixes, atomics), as a CLI, an LSP server and a VS Code extension.

     contrib/systemd/

    Nightly benchmarks

    mjwarp-nightly.timer fires at 02:00 daily (RandomizedDelaySec=1800, Persistent=true) and starts mjwarp-nightly.service, which runs ~/.local/bin/mjwarp-sweep --daily forward (sweep.py installed under that name).

     contrib/xml/ + Apollo notebook

    Apollo locomotion

    xml/apptronik_apollo.xml and xml/scene.xml are the Apptronik Apollo humanoid used by apptronik_apollo_locomotion.ipynb, a notebook that trains the humanoid to walk with Brax PPO (MJX with the Warp back end).

    Pitfall: the nconmax trap in contrib

    Both jax_unroll.py and the Apollo notebook pass a total contact budget as nconmax. In 4.0.1 nconmax is per world (io.py::put_data docstring), so the old lines allocate nworld times too many slots. Pass the per-world number, or use naconmax for the total (Ch 28 §6).

    8The notebook: notebooks/tutorial.ipynb

    Repo only: the official MJWarp tutorial. Ch 1 uses it as the install check (put_model(from_xml_string('<mujoco/>'))). The course's own notebooks live in this course's notebooks/ folder, one per chapter, each with an Open-in-Colab link on its chapter page.
