A B-tree keeps a few sorted keys in every node and all leaves at one depth. Watch a search read one node per level, let the invariant checker find what is wrong with a damaged tree, and unfold a 2-3-4 tree into the red-black tree it is equivalent to.

This page belongs to Chapter 03: B-tree structure and search. All trees have order M: a node has at most M children and M − 1 keys, and every node except the root has at least ⌈M/2⌉ − 1 keys. The first tree is the guide's canonical example: the tree that inserting 10, 20, 5, 6, 12, 30, 7, 17, 3, 25, 1, 15 produces at M = 4. Every frame is computed by a JavaScript model that follows the chapter's Zig and Rust code; the badges at the bottom of the page compare it with the programs' output.

2. The invariant checker on broken trees

Each choice damages the canonical tree in one way. validate walks the tree from the root, hands every child the range its keys must lie in, and stops at the first violation. Compare its verdict with the number of keys that get still finds: several kinds of damage are invisible to lookups.

3. A 2-3-4 tree is a red-black tree

A B-tree of order 4 is also called a 2-3-4 tree (every interior node has 2, 3 or 4 children). Split each node into one black binary node and up to two red ones and you get a red-black tree with the same keys.
