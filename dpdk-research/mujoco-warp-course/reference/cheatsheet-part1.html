    1Part I at a glance

    Every MJWarp program has the same shape: compile with ordinary MuJoCo on the host, copy the model to the device once, allocate nworld worlds once, step all of them in one call, and copy one world home only when you want to look at it.

    2The four calls

    import mujoco
import numpy as np
import warp as wp
wp.config.log_level = wp.LOG_WARNING      # quiet the module-load log (Ch 4 §8)
import mujoco_warp as mjw

ON_GPU = wp.get_device().is_cuda
NWORLD = 4096 if ON_GPU else 8

mjm = mujoco.MjModel.from_xml_string(XML)                    # 1. compile on the host
m = mjw.put_model(mjm)                                        # 2. model to the device
d = mjw.make_data(mjm, nworld=NWORLD, nconmax=8, njmax=32)    # 3. all worlds (host model!)
for _ in range(1000):
    mjw.step(m, d)                                            # 4. every world, one call
assert not d.overflow.numpy().any()                           # size the buffers (Ch 9)
mjd = mujoco.MjData(mjm)
mjw.get_data_into(mjd, mjm, d, world_id=0)                    # look at world 0 on the host
    CallTakesDoesRead more
    mjw.put_model(mjm, batch_sizes=None)host MjModelRaises NotImplementedError for unsupported features before allocating; float32 device arrays; adds warp-only fields and options; opt.tolerance = max(tolerance, 1e-6).Ch 5 §2
    mjw.make_data(mjm, nworld=1, nconmax, njmax, ...)host MjModelAllocates every buffer once. Default pose qpos0; derived fields (xpos, contacts, sensors) are zero until forward.Ch 5 §4
    mjw.put_data(mjm, mjd, nworld=1, ...)host model + MjDataCopies one host state into every world (and runs host kinematics on mjd, so it mutates it).Ch 5 §4
    mjw.step(m, d) / mjw.forward(m, d)device m, dstep = forward + integrator; only step advances d.time (float32: 11 steps of 0.01 read 0.109999985).Ch 5 §5
    mjw.get_data_into(result, mjm, d, world_id=0)an existing MjDataFilters the pooled contacts, reorders efc rows, about 140 host copies.Ch 5 §6

    C MuJoCo to MJWarp translation table: Ch 2 §13. Setup cell and the GPU check: Ch 1 §5.

    3Shape rules

    WhatShape (Warp)Rule
    Every mjw.Data array(nworld, <MuJoCo size>)Row w is world w: d.qpos (nworld, nq), d.qvel (nworld, nv), d.ctrl (nworld, nu).
    Vector dtypes (vec3, quat, mat33, spatial_vector)d.xpos (nworld, nbody) of vec3One Warp element; .numpy() adds the trailing dims: (nworld, nbody, 3).
    Pool countersd.nacon (1,), d.ncollision (1,)The only Data arrays without a world axis. Filled slots: min(d.nacon[0], d.naconmax).
    Contactsd.contact.* (naconmax, ...)One shared pool, each slot tagged contact.worldid; not contiguous per world, not sorted.
    Constraint rowsd.efc.* (nworld, njmax)Per world; njmax is a hard per-world cap, nconmax only sizes the pool.
    Batched ("*") Model field(B, ...), B = 1 by defaultKernels read field[worldid % field.shape[0]]: round robin, not blocks (Ch 6 §7).
    Structural Model fieldsno batch axisSizes, topology, types: shared by all worlds.
    Bytesrow-majoroffset = ((w·nbody + b)·3 + k)·4 for a float32 vec3; dim=(nworld, n) launches read contiguous memory (Ch 6 §3).

    Find a joint's slots

    j = mujoco.mj_name2id(mjm, mujoco.mjtObj.mjOBJ_JOINT, "hinge")
qadr, vadr = mjm.jnt_qposadr[j], mjm.jnt_dofadr[j]
q = d.qpos.numpy()[:, qadr]          # one value per world

    Free joint 7 qpos / 6 qvel, ball 4 / 3, slide and hinge 1 / 1 (Ch 2 §3).

    One world's contacts

    n = min(int(d.nacon.numpy()[0]), d.naconmax)
mine = d.contact.worldid.numpy()[:n] == w
dist_w = d.contact.dist.numpy()[:n][mine]

    Pooled layout: Ch 6 §8; the pool in depth: Ch 9 §2.

    Quaternions are (w, x, y, z)

    Identity (1, 0, 0, 0) in MuJoCo and in MJWarp's math.py funcs. Warp's built-in wp.quat stores (x, y, z, w): never feed one to the other unconverted (Ch 2 §3, Ch 4 §6).

    4Writing inputs: assign, never replace

    CallEffectTypical use
    d.qpos.assign(np_array)copies into the existing array (same pointer)initial states from NumPy
    wp.copy(d.ctrl, src)device-to-device (or host-to-device) copyactions from a policy buffer
    d.ctrl.fill_(v) / d.qfrc_applied.zero_()sets every elementsame value in all worlds; clear forces

    your own @wp.kernelwrites on the device, no host round tripresets, randomization (Ch 8, Ch 10)

    Pitfall: .assign checks bytes, not shapes

    An array of the right total size but the wrong shape is accepted. Build inputs as (nworld, n) float32 and compare shapes yourself. On a GPU, .numpy() is an allocation, a copy and a sync, and writing into its result changes nothing on the device; on Warp's CPU device it is a live view (add .copy() to keep a snapshot) (Ch 6 §5, §10).

    5m.opt: arrays vs Python ints

    The split that matters is storage, not MuJoCo vs warp-only. Defaults below are what put_model produces for an MJCF that sets nothing (values printed by the 4.0.1 wheel).

    Arrays (1,): can become per world

    timestep 0.002, gravity (0, 0, -9.81), wind, magnetic, density 0, viscosity 0, tolerance 1e-6 (clamped), ls_tolerance 0.01, noslip_tolerance, ccd_tolerance 1e-6, sleep_tolerance, impratio_invsqrt 1.

    m.opt.timestep.fill_(0.005)                     # in place: live
m.opt.gravity.assign([[0, 0, -3.7]])
m.opt.timestep = wp.array(np.full(NWORLD, 0.002), dtype=float)  # per world (Ch 10 §9)

    Python ints / bools: same for all worlds

    integrator EULER(0), cone PYRAMIDAL(0), solver NEWTON(2), iterations 100, ls_iterations 50, ccd_iterations 35, sdf_initpoints 40, sdf_iterations 10, disableflags 0, broadphase (picked by put_model), broadphase_filter 11, graph_conditional True, warn_overflow 4095, deterministic 0.

    Read while dispatching, some baked in with wp.static: changing one can recompile, and always needs a graph recapture (Ch 24 §4).

    Full field table and the tolerance clamp: Ch 5 §3. ls_parallel raises AttributeError (removed in 3.9.1).

    6Warp in one card each

    A kernel, one thread per world

    @wp.kernel
def push(force: float, qfrc_applied_out: wp.array2d[float]):
    worldid = wp.tid()
    qfrc_applied_out[worldid, 0] = force

wp.launch(push, dim=d.nworld, inputs=[1.0],
          outputs=[d.qfrc_applied])

    Typed parameters, no return value, typed locals in loops (total = float(0.0)). dim=0 is a no-op; for 2-D launches the last index is fastest (Ch 4 §3).

    Devices and arrays

    wp.get_device()               # cuda:0 or cpu
wp.get_cuda_device_count() > 0  # else Warp silently runs on CPU
a = wp.zeros((nworld, 3), dtype=float)
a.numpy()                     # GPU: sync + copy

    A wp.array has a dtype, a shape and a device (Ch 4 §1, §2).

    How the GPU runs it

    • 32 lanes form a warp and run in lockstep; divergent branches cost both sides.
    • Neighbouring lanes should read neighbouring addresses (coalescing).
    • Small launches leave most SMs idle; one world alone is not faster than C MuJoCo.
    • Warp's CPU device: block size 1, correct, not fast.

    Ch 4 §4, Ch 6 §11

    Compile, cache, time

    • The first call JIT-compiles; modules are cached on disk by hash. wp.static specializes at code generation (Ch 4 §8, §7).
    • Float atomics depend on arrival order (Ch 4 §9).
    mjw.step(m, d); wp.synchronize()   # warm up
t0 = time.perf_counter()
for _ in range(n): mjw.step(m, d)
wp.synchronize()                    # launches are async
dt = (time.perf_counter() - t0) / n

    7The pipeline map

    Stage order of mjw.step (4.0.1 wheel): kinematics → crb → collision → make_constraint → [island] → transmission → sensor_pos → velocity → sensor_vel → control callback → actuation → acceleration → solve → [rne_postconstraint] → sensor_acc → integrate (Ch 7 §2). The integrator's _advance moves qpos, qvel, act, time and copies qacc into qacc_warmstart.

    Force budget

    # fwd_acceleration, per (world, dof), to the last bit:
qfrc_smooth = (qfrc_passive - qfrc_bias + qfrc_actuator
               + qfrc_applied + J^T xfrc_applied)
# M qacc_smooth = qfrc_smooth; the solver adds qfrc_constraint

    Ch 7 §5; every term in Part III's sheet.

    Switch stages off

    m.opt.disableflags |= mjw.DisableBit.CONTACT   # Python int
m.opt.disableflags = 0                          # eager: change any time
# graphs: recapture after a change (Ch 24)

    Bits: CONSTRAINT 1, EQUALITY 2, FRICTIONLOSS 4, LIMIT 8, CONTACT 16, SPRING 32, DAMPER 64, GRAVITY 128, CLAMPCTRL 256, WARMSTART 512, FILTERPARENT 1024, ACTUATION 2048, REFSAFE 4096, SENSOR 8192, EULERDAMP 32768, NATIVECCD, ISLAND, MULTICCD. No MIDPHASE, no AUTORESET (Ch 7 §7).

    Factorize pairing

    One factorization of M per qpos: _forward factors inside fwd_acceleration(factorize=True); the public stage functions factor in fwd_position(). Calling stages by hand in the wrong pairing solves with a stale factor (Ch 7 §3).

    Launches and timing

    About 100 launches per step (95 + 5 tiled for PLAYGROUND, 89 + 6 for the humanoid); features change the count, sizes go into dim (Ch 7 §8). Time stages with wp.synchronize() on both sides; EventTracer is GPU only, guard it with enabled=ON_GPU (Ch 7 §9).

    Which field each stage writes: the Part III stage → Data map and Ch 7 §4.

    8Seeing a world

    Path 1: copy one world, use mujoco.Renderer

    import os
os.environ.setdefault("MUJOCO_GL", "egl")   # BEFORE import mujoco
import mujoco
mjw.get_data_into(mjd, mjm, d, world_id=0)
with mujoco.Renderer(mjm, 240, 320) as r:
    r.update_scene(mjd); img = r.render()

    Path 2: batch renderer, all worlds

    rc = mjw.create_render_context(mjm, nworld=N, cam_res=(W, H))
mjw.forward(m, d); mjw.refit_bvh(m, d, rc); mjw.render(m, d, rc)
rgb = wp.zeros((N, H, W), dtype=wp.vec3)
mjw.get_rgb(rc, 0, rgb)

    Needs no OpenGL; works on Warp's CPU device too (slowly). Owner: Ch 27 §4.

    9Pitfalls

    • Warp silently on CPU. Check wp.get_cuda_device_count() > 0 in the setup cell; everything still runs, slowly (Ch 1 §5).
    • The first call is slow. It compiles kernels; warm up before timing (Ch 4 §8).
    • Derived fields are zero after make_data. Call mjw.forward before reading xpos, sensors or contacts (Ch 5 §4).
    • float32, not float64. Agreement with C MuJoCo is about 1e-6 per step; chaotic scenes amplify it, so compare statistics, not trajectories (Ch 5 §7).
    • Default buffer sizes are a guess (48 contacts, 64 rows per world for a rigid model). Pass nconmax/njmax and check d.overflow (Part II sheet).
    • Replacing arrays disconnects graphs and views; assign instead (Ch 6 §5).
    • get_data_into in a loop costs about 140 host copies per call; record on the device and read once (Ch 5 §6).
    • Unsupported in 4.0.1: PGS, NaN checks and auto-reset, float64, PID and SO3 actuators, body/actuator/sensor plugins, some flex combinations; put_model raises NotImplementedError (Ch 1 §7).
