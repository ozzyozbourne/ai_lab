# Chapter 10 code: Capstone, an end-to-end eval suite for ShopDesk and its RL environment

Standard library + NumPy only. No network, no API keys, no model calls: every agent, user, judge and
tool backend is a seeded mock, so the same command prints the same numbers that appear in the chapter.
Every script runs from any working directory (it adds its own folder to `sys.path`) and finishes in
under 10 s; `python3 code/run_all.py ch10` runs them all.

## Package `evalsuite/`

| Module | What it holds |
|---|---|
| `env.py` | `ShopDeskEnv` (`ShopDesk-v1`): Gymnasium-style `reset(seed)` / `step(action)` 5-tuple, tool backend, `state_hash`, step limit -> `truncated`, deep-copy isolation, seeded bugs for QA |
| `tasks.py` | 17 templates x 7 slices -> 210 tasks, dev/test split, canary, content hashes, buggy impossible spec `v0`, `benign_twin`, `task_from_production_failure` |
| `users.py` | scripted user simulator with four personas (verbose, terse, forgetful, typo) |
| `text.py` | reply templates with ground-truth tone, tool-call formatting, the agents' message parser |
| `agents.py` | null, random, gold, escalate, `KnobAgent` (v1, v2, v2_spotlight, v2.1_regressed, careful, sloppy, oracle) |
| `adversaries.py` | red-team agents: hacker (`claim_only`, `fake_id`, `shotgun`), leak exploiter, leaky refuser |
| `graders.py` | AST tool-call checker, state-hash grader (plus `state_ok_any` for alternative goal states), required-output check with exclusive answers, policy checker (leaks = any field the requester does not own), weak v0 grader, trace grader, mock tone judge; `GRADER_VERSION`, `GRADER_HASH`, `JUDGE_VERSION` for the card header |
| `card.py` | the six brief criteria, task-bootstrap CIs plus cluster-adjusted Wilson for proportions, meets / inconclusive / misses verdicts (also at a Bonferroni-adjusted level) |
| `stats.py` | Wilson, clustered SE, paired cluster bootstrap, McNemar, pass@k, pass^k, MDE, kappa, IQM, PPI, PSI (`python3 evalsuite/stats.py` self-tests) |
| `qa.py` | environment QA: gold, null, determinism, leakage, isolation, user simulator (gold + oracle over 5 seeds) |
| `runner.py` | trials with a fresh env, `infra_error` + retry, cost and latency, JSONL transcripts, span records |

| File | Section | What it shows | Command |

| `validate_judge.py` | 10.6 `#graders` | tone judge v1 vs v2 on dev, v2 on test (TPR 0.71, TNR 1.00, kappa 0.72 with CIs), swap test, PPI coverage 95% vs judge-only 0% | `python3 code/ch10/validate_judge.py` |
| `run_suite.py` | 10.7, 10.9 `#results` `#transcripts` | v1 vs v2 results card (header pins env, dataset, grader version + hash, judge, seed) with bootstrap and cluster-Wilson CIs and meets / inconclusive / misses verdicts, plus a Bonferroni column, retry neutrality, per-component rates, per-slice CIs, pass^k, paired bootstrap + McNemar, task- and template-level MDE, cost/latency, trace grader, spans; writes `data/results.json` | `python3 code/ch10/run_suite.py` |

| `ci_gate.py` | 10.11 `#ci` | regression (100%) + paired non-inferiority gate, exit codes; A/A margin calibration; PSI drift; production failure -> task | `python3 code/ch10/ci_gate.py` |

`python3 code/ch10/ci_gate.py --candidate v2.1_regressed --baseline v2` exits with status 1.
`train_rl.py` is the slowest (about 8 s).

`data/transcripts_*.jsonl` are regenerated by `run_suite.py` and ignored by git (`code/ch10/.gitignore`).
