Chapter 02

Building DPDK and Your First Application (Build, Link, main() and Options)

You will build a DPDK program from an empty directory, link it correctly against an installed DPDK, split the command line between DPDK and your own code, and explain the two linking mistakes that make a perfectly good program find zero network ports.

  • Beginner
  • ~75 min
  • Prerequisites: ch1
  • rte_eal_init
  • rte_exit
  • rte_eal_cleanup
  • rte_version
Learning objectives
  • Describe the DPDK source tree, the meson/ninja build, the options that shape it and what meson install puts on disk.
  • Compile and link your own program against DPDK with pkg-config, from a Makefile and from a meson project.
  • Explain how drivers register themselves with constructors before main(), and why a static link without --whole-archive silently loses every driver.
  • Write a correct main(): call rte_eal_init(), shift argc/argv, parse your own options after --, and exit with rte_exit() or rte_eal_cleanup().
  • Diagnose a shared build that aborts with Cannot init plugins, and say how real deployments avoid it.
  • Run testpmd on two software ports and read its counters (a first look at what chapters 3 to 8 explain).
Tools for this chapter

  • pkg-config: reads libdpdk.pc and prints compiler and linker flags.

  • dpdk-pmdinfo.py (in usertools/, installed to bin/): lists the drivers inside a binary.
  • dpdk-testpmd and the prebuilt dpdk-skeleton example: the first-look lab.

1The big picture: from source tree to running binary

DPDK is not one library. It is about sixty libraries (lib/), a few hundred drivers (drivers/), tools (app/, usertools/) and examples (examples/). You do not link "DPDK" by hand; you build and install it once, and then every program you write asks a small text file, libdpdk.pc, which compiler and linker flags it needs. 2Building DPDK with meson and ninja

meson is a build configurator: it reads meson.build files and your options, checks the compiler and the system libraries, and writes a build.ninja file. ninja then runs the actual compiler commands, in parallel. The standard sequence, from doc/guides/linux_gsg/build_dpdk.rst, is:

# from the top of the DPDK source tree
meson setup build                      # configure into ./build (options: -Dname=value)
meson configure build -Dexamples=all   # change options later, then rebuild
ninja -C build                         # compile everything
meson install -C build                 # copy headers, libs, drivers, tools, libdpdk.pc
ldconfig                               # refresh the shared-library cache (system prefix only)

Reference: link-time optimisation (LTO) in one paragraph (collapsed)

Configure with meson setup build -Db_lto=true and the compiler keeps its intermediate representation in every object file, then optimises the whole program at link time. That lets it inline a small function from librte_mbuf into librte_ethdev or into your code, across library boundaries that normally stop inlining. DPDK needs fat LTO objects (-ffat-lto-objects, added by config/meson.build) because pmdinfogen must still read normal ELF objects during the build. The gain depends on the code; measure it (ch22). Source: doc/guides/prog_guide/lto.rst.

Reference: other platforms (collapsed)

The same meson flow works on FreeBSD (doc/guides/freebsd_gsg/index.rst) and Windows (doc/guides/windows_gsg/index.rst, with clang or MSVC; fewer drivers). Cross-compiling for Arm uses a cross file: meson setup arm-build --cross-file config/arm/arm64_armv8_linux_gcc (doc/guides/linux_gsg/cross_build_dpdk_for_arm64.rst). This course only uses Linux on x86-64.

3What gets installed, and the version numbers

meson install copies everything under the install prefix (default /usr/local; this course uses $DPDK_PREFIX, a directory under /tmp). Figure 2 shows the real layout with real counts.

Three version numbers

  • Release 26.11.0 (file VERSION): year.month.patch. Releases come out in March, July and November; the November one (YY.11) is the long-term-support (LTS) release that keeps receiving fixes for years.
  • ABI 27.0 (file ABI_VERSION): the binary interface version. It becomes the soname librte_eal.so.27 and the driver directory pmds-27.0. A program linked against .so.27 keeps working with any later library that keeps ABI 27; the ABI only changes at the yearly LTS release.
  • API: in your code. RTE_VERSION is a compile-time number built with RTE_VERSION_NUM(year, month, minor, release) from lib/eal/include/rte_version.h; rte_version() returns the run-time string of the library actually linked in ("DPDK 26.11.0"). Use the macro in #if to support several DPDK versions from one source file.

Functions marked __rte_experimental are outside the ABI promise. Using one without -DALLOW_EXPERIMENTAL_API gives a deprecation warning (you will see it in section 9). __rte_internal functions are for drivers only; calling one needs -DALLOW_INTERNAL_API and is a hard error otherwise (ch23 writes a driver and needs it). Both are defined in lib/eal/include/rte_compat.h.

4Consuming DPDK: pkg-config

pkg-config reads .pc files from the directories in PKG_CONFIG_PATH. For DPDK you need three queries:

$ pkg-config --libs libdpdk
-Wl,--as-needed -L$DPDK_PREFIX/lib/x86_64-linux-gnu -lrte_node -lrte_graph … -lrte_eal -lrte_pmu -lrte_telemetry -lrte_argparse -lrte_kvargs -lrte_log
$ pkg-config --libs --static libdpdk
-Wl,--whole-archive -L$DPDK_PREFIX/lib/x86_64-linux-gnu -l:librte_bus_pci.a -l:librte_bus_vdev.a -l:librte_mempool_bucket.a … -l:librte_net_null.a … -l:librte_eal.a … -l:librte_log.a -Wl,--no-whole-archive -Wl,--export-dynamic … -lnuma -lpcap -larchive -lxdp -lbpf -lcrypto -lz -lelf …

Two details in the compile flags matter. -include rte_config.h force-includes the configuration header in every file. -march=native comes from platform=native: DPDK headers contain inline functions that use AVX2/AVX-512 here, so the binary may not run on an older CPU. Build DPDK with -Dplatform=generic if you ship binaries to other machines.

The static list is the interesting one. Drivers and libraries are wrapped in -Wl,--whole-archive … -Wl,--no-whole-archive, then come the system libraries the drivers need. libdpdk.pc and the internal libdpdk-libs.pc are split exactly so that pkg-config prints things in this order. Section 6 explains why the bracket is essential.

A Makefile that uses it

This is the chapter's Makefile, modelled on examples/helloworld/Makefile. It builds the same hello.c as a static program (hello) and as a shared one (hello_shared), and it builds the deliberately broken ports_broken.

code/Makefilemake
# SPDX-License-Identifier: BSD-3-Clause
# Chapter 2 Makefile: build DPDK applications against an installed DPDK
# using pkg-config. Run "source <dpdk-env.sh>" first so that pkg-config
# can find libdpdk.pc (PKG_CONFIG_PATH).

PKGCONF ?= pkg-config

ifneq ($(shell $(PKGCONF) --exists libdpdk && echo 0),0)
$(error "no installation of DPDK found (is PKG_CONFIG_PATH set?)")
endif

CFLAGS  += -O2 -g -Wall -Wextra $(shell $(PKGCONF) --cflags libdpdk)

# Static link (the course default). The output starts with
#   -Wl,--whole-archive -l:librte_bus_pci.a ... -l:librte_log.a -Wl,--no-whole-archive
# so that every driver's constructor is kept.
LDLIBS_STATIC = $(shell $(PKGCONF) --libs --static libdpdk)

# Shared link: only -L<libdir> -lrte_xxx; drivers are loaded at run time
# from the plugin directory (RTE_EAL_PMD_PATH) or from -d <path>.
LDLIBS_SHARED = $(shell $(PKGCONF) --libs libdpdk)

# The pitfall: the same static flags with the --whole-archive bracket removed.
comma := ,
LDLIBS_BROKEN = $(filter-out -Wl$(comma)--whole-archive -Wl$(comma)--no-whole-archive,$(LDLIBS_STATIC))

APPS = hello args ports_ok ports_broken hello_shared verbose

all: $(APPS)

hello: hello.c
	$(CC) $(CFLAGS) $< -o $@ $(LDLIBS_STATIC)

args: args.c
	$(CC) $(CFLAGS) $< -o $@ $(LDLIBS_STATIC)

# make pitfall -> both port counters
pitfall: ports_ok ports_broken

ports_ok: ports.c
	$(CC) $(CFLAGS) $< -o $@ $(LDLIBS_STATIC)

ports_broken: ports.c
	$(CC) $(CFLAGS) $< -o $@ $(LDLIBS_BROKEN)

# make shared -> hello linked against the .so files
shared: hello_shared

hello_shared: hello.c
	$(CC) $(CFLAGS) $< -o $@ $(LDLIBS_SHARED)

# Exercise 1 solution
verbose: solutions/verbose.c
	$(CC) $(CFLAGS) $< -o $@ $(LDLIBS_STATIC)

clean:
	rm -f $(APPS)
	rm -rf mesonapp/build

.PHONY: all pitfall shared clean

Line 12: pkg-config --cflags goes into CFLAGS. Line 17: the static list goes at the end of the link command, after your source or objects, because the linker resolves symbols left to right. Line 21: the shared list. Line 25: the broken variant, made with make's filter-out to delete the two --whole-archive words.

5Your first program: hello.c

Here is the DPDK "hello world" (compare examples/helloworld/main.c), rewritten with comments. It does five things: start the EAL, print versions, run a function on every lcore, count ports, and clean up.

code/hello.cC
/* SPDX-License-Identifier: BSD-3-Clause
 *
 * hello.c - Chapter 2: the smallest useful DPDK program, written from scratch.
 *
 * What it shows:
 *   1. rte_eal_init() is the first DPDK call; it eats the EAL options.
 *   2. Work is launched on every lcore (details of launching: ch3).
 *   3. rte_version() and rte_eth_dev_count_avail() prove that the library
 *      and the drivers (PMDs) really are inside this binary.
 *   4. rte_eal_cleanup() releases what rte_eal_init() took.
 *
 * Build:  make hello
 * Run:    ./hello -l 0-1 --no-pci --no-huge -m 64 --file-prefix=ch02-hello
 */
#include <stdio.h>
#include <stdlib.h>

#include <rte_eal.h>      /* rte_eal_init(), rte_eal_cleanup() */
#include <rte_lcore.h>    /* rte_lcore_id(), RTE_LCORE_FOREACH_WORKER */
#include <rte_launch.h>   /* rte_eal_remote_launch(), rte_eal_mp_wait_lcore() */
#include <rte_version.h>  /* rte_version(), RTE_VERSION, RTE_VERSION_NUM() */
#include <rte_ethdev.h>   /* rte_eth_dev_count_avail() */
#include <rte_common.h>   /* rte_exit() (lives in rte_common.h in 26.11) */

/* The function every lcore runs. It must have the lcore_function_t shape:
 * int fn(void *arg). */
static int
lcore_hello(void *arg)
{
	(void)arg;
	printf("hello from lcore %u\n", rte_lcore_id());
	return 0;
}

int
main(int argc, char **argv)
{
	unsigned int lcore_id;

	/* Step 1: initialise the EAL. It parses (and consumes) the EAL options,
	 * creates one thread per extra lcore, sets up memory and probes devices. */
	int ret = rte_eal_init(argc, argv);
	if (ret < 0)
		rte_exit(EXIT_FAILURE, "Cannot init EAL\n");

	/* Compile-time version (from the headers) vs run-time version (from the
	 * library that is actually linked in). */
#if RTE_VERSION >= RTE_VERSION_NUM(26, 11, 0, 0)
	printf("compiled against DPDK >= 26.11, running %s\n", rte_version());
#else
	printf("compiled against an older DPDK, running %s\n", rte_version());
#endif

	/* Step 2: run lcore_hello() on every worker lcore ... (launch: ch3) */
	RTE_LCORE_FOREACH_WORKER(lcore_id)
		rte_eal_remote_launch(lcore_hello, NULL, lcore_id);

	/* ... and on the main lcore too, then wait for the workers. */
	lcore_hello(NULL);
	rte_eal_mp_wait_lcore();

	/* Step 3: how many Ethernet ports did the EAL probe? Each --vdev=net_*
	 * adds one, but only if its driver was linked into this binary. */
	printf("lcores=%u ports=%u\n", rte_lcore_count(),
	       (unsigned int)rte_eth_dev_count_avail());

	/* Step 4: give back hugepages/memory, threads, and runtime files. */
	rte_eal_cleanup();
	return 0;
}
  • Lines 42-44. rte_eal_init() must be the first DPDK call. It parses the EAL options, reserves memory, starts one thread per extra lcore, and scans buses for devices. On failure it returns -1 and sets rte_errno; there is no point continuing.
  • Lines 48-52. Compile time vs run time: RTE_VERSION comes from the headers you compiled with; rte_version() from the library you run with. They differ only with shared libraries.
  • Lines 56-60. Launch lcore_hello on every worker lcore, run it on the main lcore too, and wait. Chapter 3 explains lcores and launching; for now, "lcore" means "a thread pinned to one CPU that EAL created for you".
  • Lines 64-65. rte_eth_dev_count_avail() counts the Ethernet ports the EAL found. We pass no device, so expect 0, then add --vdev=net_null0.
  • Line 68. rte_eal_cleanup() releases memory, stops the lcore threads and removes runtime files. Call it before you return from main().

Exiting: rte_exit() vs return

rte_exit(code, fmt, ...) logs the message at CRIT level (plus Error - exiting with code: N when the code is non-zero), calls rte_eal_cleanup(), and then calls exit(). Use it for fatal errors anywhere. In 26.11 it is declared in lib/eal/include/rte_common.h and implemented in lib/eal/common/eal_common_debug.c. Its harsher sibling rte_panic() also prints a stack trace and calls abort() (core dump): use it for "this cannot happen" bugs. A normal end is rte_eal_cleanup(); return 0;. After rte_eal_cleanup() no DPDK function may be called.

6Constructors and the --whole-archive pitfall

Your code never mentions net_null. So how does --vdev=net_null0 find a driver? Every driver ends with a registration macro. The null driver's last lines are (drivers/net/null/rte_eth_null.c):

RTE_LOG_REGISTER_DEFAULT(eth_null_logtype, NOTICE);   /* line 81  */
RTE_PMD_REGISTER_VDEV(net_null, pmd_null_drv);        /* line 775 */

and the macro expands to a constructor: a function that the C runtime runs before main() (drivers/bus/vdev/bus_vdev_driver.h, lib/eal/include/rte_common.h):

#define RTE_PMD_REGISTER_VDEV(nm, vdrv)\
RTE_INIT(vdrvinitfn_ ##vdrv)\
{\
	(vdrv).driver.name = RTE_STR(nm);\
	rte_vdev_register(&vdrv);\
} \
RTE_PMD_EXPORT_NAME(nm)

#define RTE_INIT(func) RTE_INIT_PRIO(func, LAST)
#define RTE_INIT_PRIO(func, prio) \
static void __attribute__((constructor(RTE_PRIO(prio)), used)) func(void)

Constructors run in priority order: RTE_PRIORITY_LOG (101) registers log types, RTE_PRIORITY_BUS (110) registers buses (RTE_REGISTER_BUS), RTE_PRIORITY_CLASS (120) registers device classes, and LAST registers drivers. When main() finally calls rte_eal_init(), the vdev bus already has a list of drivers and can match the name net_null0 to the driver net_null.

Now the trap. A static library (.a) is a bag of object files. By default the linker copies an object file into your program only if it defines a symbol that something already in the program needs. Nothing calls vdrvinitfn_pmd_null_drv; it is only listed in the object's .init_array. So without help, the linker throws the whole driver away. -Wl,--whole-archive says "take every object from the following archives, needed or not".

The numbers in the widget (712 vs 351 constructors, 2 buses, 21 drivers) are measured from the two real binaries below with readelf and nm. Here is the program; it only counts ports:

code/ports.cC
/* SPDX-License-Identifier: BSD-3-Clause
 *
 * ports.c - Chapter 2: the --whole-archive pitfall.
 *
 * The program only counts Ethernet ports. It is linked twice by the Makefile:
 *   ports_ok      $(pkg-config --libs --static libdpdk)
 *                 -> drivers are wrapped in -Wl,--whole-archive, every PMD
 *                    constructor is kept, --vdev=net_null0 creates a port.
 *   ports_broken  the same archives, but WITHOUT --whole-archive
 *                 -> nothing in this file references a driver symbol, so the
 *                    linker drops every driver object file, the RTE_INIT
 *                    constructors never run, no driver registers, 0 ports.
 */
#include <stdio.h>
#include <stdlib.h>

#include <rte_eal.h>
#include <rte_common.h>
#include <rte_ethdev.h>

int
main(int argc, char **argv)
{
	int ret = rte_eal_init(argc, argv);
	if (ret < 0)
		rte_exit(EXIT_FAILURE, "Cannot init EAL\n");

	uint16_t n = rte_eth_dev_count_avail();
	printf("ports=%u\n", (unsigned int)n);

	uint16_t port;
	RTE_ETH_FOREACH_DEV(port) {
		struct rte_eth_dev_info info;
		if (rte_eth_dev_info_get(port, &info) == 0)
			printf("  port %u: driver %s\n", (unsigned int)port, info.driver_name);
	}

	rte_eal_cleanup();
	return n == 0 ? 1 : 0;   /* non-zero exit when no port was found */

7Anatomy of main() and the -- separator

A DPDK program's command line has two halves: options for the EAL, then --, then options for your application.

./args -l 0 --no-pci --no-huge -m 64 --file-prefix=ch02-args -- --count 3 --name demo
#      \_________________ EAL options _______________________/  \__ app options __/

rte_eal_init(argc, argv) parses the EAL half and returns how many argv entries it consumed (including the --). Before returning it copies the program name into the last consumed slot. So the two lines found in every DPDK example, argc -= ret; argv += ret;, leave you with an ordinary argv whose element 0 is the program name and whose remaining elements are only your options. Figure 3 shows this with the real numbers from the run below.

code/args.cC
/* SPDX-License-Identifier: BSD-3-Clause
 *
 * args.c - Chapter 2: how EAL options and application options share argv.
 *
 *   ./args <EAL options> -- <application options>
 *
 * rte_eal_init() parses everything up to (and including) the "--" separator
 * and returns how many argv entries it consumed. We shift argc/argv by that
 * amount (EAL has already copied the program name into the slot that held
 * "--", so the new argv[0] is the program name again) and hand the rest to
 * plain getopt_long(). Words without a leading dash that appear before "--"
 * are not EAL options: EAL moves them behind its own, so the app gets them.
 *
 * Run: ./args -l 0 --no-pci --no-huge -m 64 --file-prefix=ch02-args \
 *             -- --count 3 --name demo
 */
#include <stdio.h>
#include <stdlib.h>
#include <getopt.h>

#include <rte_eal.h>
#include <rte_common.h>
#include <rte_lcore.h>

/* Application settings with defaults. */
static unsigned int app_count = 1;
static const char *app_name = "world";

static void
usage(const char *prog)
{
	printf("usage: %s [EAL options] -- [--count N] [--name NAME]\n", prog);
}

/* Parse the application part of the command line with ordinary getopt. */
static int
parse_app_args(int argc, char **argv)
{
	static const struct option longopts[] = {
		{ "count", required_argument, NULL, 'c' },
		{ "name",  required_argument, NULL, 'n' },
		{ "help",  no_argument,       NULL, 'h' },
		{ NULL, 0, NULL, 0 }
	};
	int opt;

	/* getopt keeps its cursor in the global optind. EAL in 26.11 parses
	 * its options with rte_argparse, but older EALs used getopt and left
	 * optind pointing past their options: always reset it to 1. */
	optind = 1;
	while ((opt = getopt_long(argc, argv, "c:n:h", longopts, NULL)) != -1) {
		switch (opt) {
		case 'c':
			app_count = (unsigned int)strtoul(optarg, NULL, 10);
			break;
		case 'n':
			app_name = optarg;
			break;
		case 'h':
		default:
			usage(argv[0]);
			return -1;
		}
	}
	return 0;
}

static void
dump_argv(const char *who, int argc, char **argv)
{
	printf("%s sees argc=%d:", who, argc);
	for (int i = 0; i < argc; i++)
		printf(" [%d]=%s", i, argv[i]);
	printf("\n");
}

int
main(int argc, char **argv)
{
	dump_argv("main() before rte_eal_init", argc, argv);

	int ret = rte_eal_init(argc, argv);
	if (ret < 0)
		rte_exit(EXIT_FAILURE, "Invalid EAL arguments\n");

	printf("rte_eal_init() consumed %d arguments\n", ret);

	/* The classic two lines found in every DPDK example. EAL copies
	 * argv[0] into the last argument it parsed (the "--"), so after the
	 * shift argv[0] is still the program name. */
	argc -= ret;
	argv += ret;
	dump_argv("app after shift", argc, argv);

	if (parse_app_args(argc, argv) < 0)
		rte_exit(EXIT_FAILURE, "Invalid application arguments\n");

	printf("app options: count=%u name=%s (EAL gave us %u lcore(s))\n",
	       app_count, app_name, rte_lcore_count());
	for (unsigned int i = 0; i < app_count; i++)
		printf("  %u: hello, %s\n", i + 1, app_name);

	rte_eal_cleanup();
	return 0;
}

After the shift, plain getopt_long() works as in any C program (lines 50-51). Reset optind = 1 first: getopt keeps its position in a global variable. (EAL 26.11 parses with rte_argparse, which does not use getopt, but older EALs did, and the reset costs nothing.) Chapter 11 replaces getopt with rte_argparse and a config file.

8Shared builds and the insecure plugin path

Linking with pkg-config --libs libdpdk (no --static) gives a 37 KB program instead of 5.1 MB. Your program now depends on librte_*.so.27 files, and drivers are not linked at all: the EAL loads them at run time as plugins, with dlopen(), from the compiled-in RTE_EAL_PMD_PATH directory and from any -d <file-or-dir> option. Failure 2: EAL refuses to load any plugin, and even -d pointing at a copy of the driver in a safe directory does not help, because the default directory is always checked as well.

Why? Before dlopen()ing a driver, verify_perms() in lib/eal/common/eal_common_options.c walks every parent directory of the plugin path, from / down, and rejects any that is world-writable (S_IWOTH). 9Your own project with meson

For a project with several files, meson is more pleasant than a Makefile. The obvious line, dependency('libdpdk'), works but links shared (and so fails here as in section 8). Two "obvious" ways to make it static both fail, which is why our meson.build takes the compile flags from the dependency and passes the static link list, untouched, to executable(link_args:):

# SPDX-License-Identifier: BSD-3-Clause
# Chapter 2: an out-of-tree meson project that links DPDK *statically*.
#
#   meson setup build && ninja -C build && ./build/app <EAL args>
#   meson setup build-bad -Dlink_mode=declare_dep   (the pitfall)
#
project('ch02-mesonapp', 'c', default_options: ['warning_level=2'])

# 1. Compile flags (include path, -include rte_config.h, -march=native)
#    come from the normal pkg-config dependency.
dpdk = dependency('libdpdk')
dpdk_cflags = dpdk.partial_dependency(compile_args: true, includes: true)

# 2. Link flags: ask pkg-config for the --static list.
pkgconf = find_program('pkg-config')
static_libs = run_command(pkgconf, '--libs', '--static', 'libdpdk',
                          check: true).stdout().strip().split()

srcs = ['main.c', 'util.c']
cargs = ['-DALLOW_EXPERIMENTAL_API']   # we call rte_cpu_socket_id()
mode = get_option('link_mode')

if mode == 'link_args'
    # Correct: pass the list unmodified through executable(link_args:), so
    # the -Wl,--whole-archive ... -Wl,--no-whole-archive bracket stays intact.
    executable('app', srcs, c_args: cargs, dependencies: dpdk_cflags,
               link_args: static_libs)
elif mode == 'declare_dep'
    # Pitfall: meson de-duplicates and reorders the link arguments of a
    # dependency object, which breaks the --whole-archive bracket.
    dpdk_static = declare_dependency(link_args: static_libs)
    executable('app', srcs, c_args: cargs,
               dependencies: [dpdk_cflags, dpdk_static])
else
    # Shared libraries: what plain dependency('libdpdk') gives you.
    executable('app', srcs, c_args: cargs, dependencies: dpdk)
endif

# link_mode=declare_dep the tempting variant that silently drops every PMD

testpmd needs a small pool here

testpmd's default mbuf pool (155,456 buffers) does not fit in --no-huge -m 256; it fails with Creation of mbuf pool for socket 0 failed: Cannot allocate memory. Every testpmd command in this course passes --total-num-mbufs=8192 (or similar). A non-interactive testpmd also needs --stats-period N and stops on SIGINT, which is why the script uses timeout -s INT.

Common pitfalls

  • No Ethernet ports / ports=0, or EAL: failed to parse device "net_null0" in a static build: the drivers were not linked. You removed or reordered -Wl,--whole-archive (hand-written link line, meson declare_dependency, a build system that "cleans up" flags). Check with dpdk-pmdinfo.py ./app; it must not print [].
  • EAL: Error, directory path /tmp is world-writable and insecure / Cannot init plugins: a shared build whose plugin directory has a world-writable parent. Install DPDK under a root-owned path, or link statically.
  • error while loading shared libraries: librte_eal.so.27: shared build, libraries not on the loader path. Use LD_LIBRARY_PATH or install to a system prefix and run ldconfig.
  • ARGPARSE: unknown argument --foo! and the program exits with code 234: an application option before --. In 26.11 EAL exits the process; your error handling after rte_eal_init() never runs.
  • The app's options are ignored or misread: you forgot argc -= ret; argv += ret; and parsed EAL's options as your own.
  • Package libdpdk was not found: PKG_CONFIG_PATH does not include <prefix>/lib/<arch>/pkgconfig. (In this course, source the environment script.)
  • Illegal instruction on another machine: the binary was built with -march=native from platform=native. Build DPDK with -Dplatform=generic for portable binaries.
  • 'rte_xxx' is deprecated: Symbol is not yet part of stable ABI: an experimental API; add -DALLOW_EXPERIMENTAL_API knowingly.
  • Output missing when the program is killed: stdout to a file or pipe is block-buffered, and a SIGINT/timeout kill loses the buffer. Use stdbuf -oL (as run.sh does) or setvbuf()/fflush().
  • A second run fails with "Cannot create lock" or "Is another primary process running?": two primaries with the same --file-prefix. Give each program its own prefix, or use --in-memory (ch4 has the full start-up error catalogue).

Exercise 4 stretch

In two sentences: why does the shared build fail on this machine, and how does a real deployment avoid it? Then find, in lib/eal/common/eal_common_options.c, the function that decides whether a build is static or shared, and say how it decides.

Answer

EAL's verify_perms() refuses to dlopen() drivers from a directory with a world-writable parent, and the compiled-in plugin directory lies under /tmp. Real deployments install DPDK in root-owned 0755 directories (distribution packages under /usr) or link statically. is_shared_build() calls dlopen("librte_eal.so.27", RTLD_LAZY | RTLD_NOLOAD): if the EAL shared library is already loaded in the process, the build is shared.

Summary
  • DPDK is built once with meson setup / ninja / meson install; options such as platform, enable_drivers and examples end up in rte_build_config.h.
  • Your program gets its flags from pkg-config --cflags libdpdk and pkg-config --libs --static libdpdk, placed after your sources.
  • Buses, classes and drivers register themselves in constructors that run before main(). A static link must keep them with -Wl,--whole-archive, or you get 0 ports or a failed rte_eal_init(). dpdk-pmdinfo.py shows what is inside.
  • main(): ret = rte_eal_init(argc, argv); check for ret < 0; argc -= ret; argv += ret;; parse your options after --; finish with rte_eal_cleanup(), or rte_exit() on fatal errors.
  • In 26.11 an unknown option before -- makes EAL exit the process; plain words are passed on to the app.
  • Shared builds load drivers from pmds-27.0 and refuse any plugin path with a world-writable parent.
  • testpmd on two net_null ports forwards tens of millions of packets per second on one lcore here: the starting point for chapters 3 to 8.
