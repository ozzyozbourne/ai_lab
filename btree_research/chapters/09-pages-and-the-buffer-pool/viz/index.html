A database file is an array of fixed-size pages, and a page number is a pointer that still works after a restart. A buffer pool keeps a few of those pages in memory. This page lets you drive one. Text of the chapter: README.md.

1. A page id is an offset

Finding page n needs no index and no directory: multiply. Move the slider.

2. The buffer pool: pins, dirty pages and the clock hand

The pool has a fixed number of frames. Fetch pins a page into a frame (reading the file only on a miss); Unpin releases it; Edit + unpin changes the page in memory and releases it as dirty. When no frame is empty the clock hand sweeps: a pinned frame is skipped, a referenced frame loses its bit and gets a second chance, and the first frame with neither is evicted. The steps loaded at the start are the fixed trace that the chapter's Zig and Rust programs print. Tick Predict to be asked which page will be evicted.

3. How many frames are enough?

The same 5000 seeded page accesses over 64 pages, replayed by this page's model against pools of different sizes. Every miss is a file read. The first setting (80% of accesses go to 8 hot pages, seed 2024) is the one the programs print; change how skewed the accesses are and watch the bars.
