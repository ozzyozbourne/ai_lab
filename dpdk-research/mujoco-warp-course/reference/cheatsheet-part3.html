    1Part III at a glance

    Every world solves M(q) q̈ + c(q, q̇) = τ + Jᵀf. Part III follows the left-hand side (kinematics, M, the bias force c) and the smooth forces τ through the pipeline, then integrates and reads sensors. The figure is the map: which stage fills which term.

    3Equation of motion and the mass matrix

    Conventions

    • Spatial vectors are (rotation, translation) for twists and wrenches, in each tree's com frame (subtree_com[body_rootid]). Exception: xfrc_applied is (force, torque) at xipos (Ch 11 §3).
    • cdof rows are the Jacobian columns in the com frame; ½ q̇ᵀ M q̇ is the kinetic energy (Ch 11 §2).
    • Kinematics runs one thread per (world, branch), root to leaf; subtrees are contiguous ranges [b, b + body_subtreenum[b]) (§5, §6).

    Factor once, solve many

    mjw.factor_m(m, d)            # d.M -> d.qLD, d.qLDiagInv
mjw.solve_m(m, d, x, y)       # x = M^-1 y (reads the factor)
mjw.mul_m(m, d, res, vec)     # res = M vec (no factor)
mjw.jac(m, d, jacp, jacr, point, body)  # (nworld, 3, nv) each
# x, y, res, vec: (nworld, nv) float arrays you allocate

    d.M is the CSR lower triangle (ancestors only, diagonal last): M_rowadr, M_rownnz, M_colind (Ch 11 §8, §9).

    Pitfall: the stale factor

    factor_m writes qLD; solve_m only reads it. Solving after a new qpos without refactoring gives a silently wrong qacc_smooth. Block families: compact, scalar Cholesky (≤ 6), tile Cholesky (≤ 64), sparse LDL with a level schedule (Ch 11 §10).

    5The actuator formula

    One formula, one thread per (world, actuator)

    ȧ = dyn(u, a)  ·  actuator_force = clamp(gain(ℓ, ℓ̇) · ũ + bias(ℓ, ℓ̇), forcerange)  ·  qfrc_actuator = momentᵀ · actuator_force. u is ctrl[w, actuator_ctrladr[i]] clamped to ctrlrange (unless CLAMPCTRL is disabled); ũ is act when the actuator has an activation, else u (actearly="true" uses the predicted next activation). Code: forward.py::_actuator_force.

    MJCF shortcuts only fill gainprm / biasprm

    Elementgainbiasforce
    <motor>10ctrl
    <position>kp-kp·ℓ - kv·ℓ̇kp(ctrl - q) - kv·q̇
    <velocity>kv-kv·ℓ̇kv(ctrl - q̇)

    AFFINE: prm[0] + prm[1]·ℓ + prm[2]·ℓ̇ (Ch 12 §7).

    Dynamics types (act_dot)

    • INTEGRATOR: ctrl; FILTER / FILTEREXACT: (ctrl - act) / dynprm[0] (FILTEREXACT integrates exactly in _advance).
    • MUSCLE: muscle_dynamics, gain/bias muscle_gain/muscle_bias (Ch 12 §9).
    • DCMOTOR: runs in 4.0.1; USER: 0, filled by m.callback.act_dyn.
    • Rejected by put_model in 4.0.1: PID dyn/gain and SO3 transmission (Ch 12 §8).

    MuJoCo 4 control slots

    nu control slots vs nactuator actuators: each actuator reads actuator_ctrladr / actuator_ctrlnum; ctrlrange has one row per slot. d.ctrl is (nworld, nu). Moment rows are sparse per world (Ch 12 §6).

    Order inside fwd_actuation

    1. _actuator_force: clamp ctrl, dyn, gain, bias, clamp force (non-tendon actuators).
    2. callbacks act_dyn, act_gain, act_bias.
    3. tendon actuators: sum per tendon, scale to actfrcrange, own forcerange.
    4. _qfrc_actuator, gravcomp, actuatorfrcrange.

    7Sensors, delays and inverse dynamics

    Slicing d.sensordata

    def sensor_slices(mjm):          # my_env, Ch 14
    return {mujoco.mj_id2name(mjm, mujoco.mjtObj.mjOBJ_SENSOR, i) or f"sensor{i}":
            (int(mjm.sensor_adr[i]), int(mjm.sensor_dim[i])) for i in range(mjm.nsensor)}
adr, dim = sensor_slices(mjm)["q1"]
q1 = d.sensordata.numpy()[:, adr:adr + dim]   # (nworld, dim)

    forward zeroes sensordata; SENSOR disable leaves all columns 0 (Ch 14 §4).

    Stage, freshness, sampling

    • POS / VEL / ACC by sensor_needstage; after step, values describe the start of the step (Ch 14 §1).
    • All 48 MuJoCo sensor types except plugins; rangefinder and contact sensors use data-field masks (§2, §5).
    • cutoff clamps; interval samples and holds, still computing every step in 4.0.1 (§6).
    • Delays: per-(world, object) ring buffers in d.history, read at t - delay (§8).

    Inverse dynamics

    d.qacc.assign(qacc_wanted)    # one world per time sample
mjw.inverse(m, d)
tau = d.qfrc_inverse.numpy()  # = M qacc + c - passive - constraint

    After forward, qfrc_inverse == qfrc_applied + qfrc_actuator. EnableBit.INVDISCRETE inverts the integrator's actual update (Ch 14 §9; project: §10).

    8Pitfalls

    • Reading cfrc_ext / cacc after a default step: not computed unless a sensor needs rne_postconstraint or opt.run_rne_postconstraint = True.
    • Stale qLD: one factorization per new qpos (Ch 11 §9).
    • njmax=0 leaves d.efc.Ma unset in 4.0.1, freezing the Euler/implicit damping solves (Ch 13 §3).
    • RK4 + step2 integrates with Euler; an RK4 control callback runs 4 times per step.
    • IMPLICIT memory grows as nworld·nbody·nv per step (about 197 MiB at nworld 4096 for the humanoid).
    • Sensors after a reset are zero until the next forward; observe from qpos/qvel when you can.
    • Fluid forces need non-zero density, viscosity or wind in the XML: has_fluid is a host flag set by put_model.
    • d.ctrl is indexed by control slot, not by actuator, in MuJoCo 4 models with multi-slot actuators.
