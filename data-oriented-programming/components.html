Components and the author API

Every shared component and figure on one page, plus the rules for writing a chapter. If something here looks wrong, it is wrong in every chapter.

API for chapter authors

The shared files (assets/book.css, assets/book.js, assets/viz/*.js without a chNN- prefix, assets/vendor/) are frozen. A chapter owns only NN-*.html, assets/viz/chNN-*.js, assets/chNN.css (styles scoped to .chNN-*), assets/data/bench-chNN.js and code/chNN-*/. Ask for core changes in scratchpad/core-requests.md.

Chapter skeleton

Chapter files sit next to index.html, so every path starts with assets/. Write only <main>: the top bar, sidebar contents, heading anchors, figure and exercise numbers, and the previous/next links are generated from Book.chapters (the manifest in book.js).

The command queue (BookQ)

Any code that needs Book goes through the queue. It works whether it runs before or after book.js: queued functions run once the page chrome is built, and later pushes run immediately.

(window.BookQ ||= []).push((B) => {
  B.selectLang("Zig");          // any Book API is safe in here
});

Registering a chapter figure

Chapter figures are named chNN-* and live in assets/viz/chNN-*.js (a classic script) or an inline <script> at the end of the page. A figure mounts once, about 300px before it scrolls into view. Any static content inside the element is a no-JS fallback and is removed when the figure mounts. A thrown error becomes a visible red box with its message, so validate opts with B.viz.check(cond, "message"). An unregistered name becomes a yellow "unknown figure" box. Registering a name twice logs a warning, and the first registration wins.

(window.BookQ ||= []).push((B) => B.viz.register("ch03-reorder", (root, opts) => {
  const n = opts.n ?? 8;
  B.viz.check(Number.isInteger(n) && n > 0, 'ch03-reorder: "n" must be a positive integer');
  const canvas = B.h("canvas", { role: "img", "aria-label": "…what it shows…" });
  const k = B.canvas(canvas, 600, 200);             // logical size; k.fit(w, h) to change it
  const C = B.colors();                              // C.pos C.vel C.hp C.flag C.pad C.hit C.miss C.line C.text C.dim …
  const cnt = B.counters([["steps", "steps"], ["miss", "misses", "bad"]]);  // <output aria-live=polite>
  let i = 0;                                         // the model
  const draw = () => {                               // pure: model → pixels + counters
    const ctx = k.ctx; ctx.clearRect(0, 0, k.width, k.height);
    /* … */ cnt.set("steps", i); cnt.set("miss", missesFor(i));
  };
  const player = B.player(root, {                    // Play/Pause · Step · Back · Reset
    step: () => (i < n ? (i++, true) : false), back: () => (i > 0 ? (i--, true) : false),
    reset: () => { i = 0; }, atEnd: () => i === n, draw, interval: 0.4,
  });                                                // reduced motion: no autoplay, shows the end state
  root.append(canvas, cnt.el, B.h("div", { class: "controls" }, player.el,
    B.segmented(["AoS", "SoA"], 0, (j) => { /* … */ draw(); }, "Layout")));
  B.onResize(root, (w) => { k.fit(w, w < 600 ? 320 : 200); draw(); }); // real CSS width: stack below 600px
  draw();
}));

Other helpers: B.h(tag, attrs, ...kids) and B.svg(...) (DOM builders; on* attributes become listeners), B.slider({label, min, max, step, value, format, oninput}), B.loop(el, (dt, t) => …) (requestAnimationFrame while on screen, never autoplays under reduced motion), B.chart(root, (width) => svg) (re-renders an SVG at the real width), B.scaleLinear/B.scaleLog, B.fmtNs, B.fmtBytes, B.fmtInt, B.rng(seed), B.reducedMotion(), B.langColor("zig"), and B.viz.empty(root, msg). Rules for figures: one idea per figure, every number computed from the model, a still frame under reduced motion, readable at 375px, and a figcaption that says what to notice.

Benchmark data

Programs print BENCH {"id":"ch04-particles","label":"SoA","lang":"rust","n":1048576,"ns":123456,"samples":[…7 sorted ns]} using the harness's emit_bench / emitBench. ns is the median time of one whole run over n elements. code/bench_all.sh collects these lines into assets/data/bench.js and assets/data/bench-chNN.js:

Book.data["ch04-particles"] = { id: "ch04-particles", machine: "Intel(R) Xeon(R) Processor @ 2.60GHz, Linux, taskset -c 2 …",
  date: "2026-11-13", source: "measured", compilers: { rust: "rustc 1.100.0 …", zig: "zig 0.17.1", odin: "odin version dev-2026-11…" },
  runs: [ { label: "AoS", lang: "rust", n: 1048576, ns: 812345, samples: [ … ] }, … ] };

Before the serial bench pass, write your dev numbers by hand to assets/data/bench-chNN.js in the same format, with source: "dev, noisy". Bind a chart with data-bench="id" on the figure body. A bare <div data-bench="id"> becomes a bench-bars. Missing data shows a grey "no data yet" box. In prose, use a live ratio with fallback text: <span data-bench-ratio="ch04-particles" data-num="AoS" data-den="SoA" data-lang="rust">about 3×</span> (optional data-n; the default is the largest n). Third-party numbers go inline with "source":"cited: …" and "metric":"value".

Absolute numbers in prose must be bound, not typed, so the serial bench pass updates them:

<span data-bench-val="ch04-update" data-label="SoA" data-lang="rust" data-n="1048576" data-metric="ns/n" data-digits="2">0.80 ns</span>
  • data-metric: "ns" (median of one run, default), "ns/n" (per element), "value" (run.value + run.unit, e.g. ch05-memory's B/node), "ms" (median in ms).
  • data-lang defaults to rust; data-n defaults to the largest n for that label and language; data-digits is significant digits (default 2).
  • The text inside is the fallback. If the id, label, language or n is missing, it stays and a console.warn names the binding (smoke.sh lists warnings but does not fail on them). Hovering a bound number shows id, label, language, n and source.
  • Ratios keep using data-bench-ratio (printed as 1.3×, 13×, 127×, 12,700×). A range across languages is two bindings: “about <span data-bench-val … data-lang="zig">…</span>–<span … data-lang="odin">…</span>”.

Live: one sequential pass costs 0.4 ns per u64 in Rust, 0.3 ns in Zig; the whole stride-16 run takes 3.6 ms in Odin.

Figure references: put fallback text inside, e.g. <a class="figref" href="#fig-x">the figure below</a>; book.js replaces it with “Figure N.M”, and print / no-JS readers still get a sentence.

Wide static SVGs (viewBox width ≥ 560) are wrapped automatically in a horizontal scroller with a minimum width, so their text stays legible on phones; a “Scroll sideways” hint appears only when the diagram actually overflows. A chapter's own overflow-x:auto figure container gets the same hint. Prefer a narrow-layout SVG when the diagram can be redrawn.

// Odin has no black_box: a volatile store keeps results alive.
@(private = "file")
sink: u64

keep :: proc "contextless" (v: $T) where size_of(T) <= 8 {
	intrinsics.volatile_store((^T)(&sink), v)
}
fn bench_runs<R>(mut f: impl FnMut() -> R) -> [Duration; RUNS] {
    black_box(f());
    let mut t = [Duration::ZERO; RUNS];
    for slot in &mut t {
        let t0 = Instant::now();
        black_box(f());
        *slot = t0.elapsed();
    }
    t.sort_unstable();
    t
}
fn nowNs(io: Io) i96 {
    return Io.Clock.awake.now(io).nanoseconds;
}
