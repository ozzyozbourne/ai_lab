Evaluations for AI: LLMs, Agents and RL Environments

An eval score is a measurement, and most of the published ones are worse measurements than they look: the parser changes the number, the judge prefers the longer answer, the agent edits the test file, and a two-point gain sits inside the error bar. This book teaches you to build evals that you can trust, for chat models, for tool-using agents, and for the RL environments that now train both. Every idea comes with the formula, a worked number, real code from the tools people use, and a small Python program you can run offline.

Contents

Part I · Foundations

  1. 01Why Evals: Foundations, Taxonomy and Eval-Driven Development What an eval is (task, trial, grader, transcript, harness), the axes every eval sits on, a ~180-line stdlib harness, and the eval-driven development loop.
  2. 02Benchmarks and Metrics for LLMs The benchmark landscape from MMLU to HLE, and every scoring rule underneath it: exact match, F1, BLEU/ROUGE, log-prob scoring, pass@k, calibration, Elo and Bradley-Terry.
  3. 03Building Eval Datasets and Fighting Contamination Golden sets from real traces, sampling, labelling guides and agreement, synthetic generation, and detecting and preventing test-set contamination.

Part II · Measuring well

  1. 04LLM-as-a-Judge and Human Evaluation Judge protocols and prompts, biases you can measure, validating judges against humans, juries, reward models, and statistically valid judge-assisted estimates.
  2. 05Statistics and Rigor in Evals Error bars, clustered and paired comparisons, power analysis, multiple comparisons, the bootstrap, nondeterminism, IRT and signal-to-noise.

Part III · Agents, environments and safety

  1. 06Evaluating AI Agents Coding, tool-use, web and computer-use agents: outcome and trajectory grading, user simulators, pass^k, cost frontiers, time horizons, harnesses and how agent benchmarks break.
  2. 07RL Environments: Rewards, Verifiers and Reward Hacking Environments as evals and as reward sources: the Gym contract, LLM-era environments, RLVR verifiers, reward hacking, environment QA and evaluating trained policies.
  3. 08Safety Evals, Red-Teaming and Dangerous Capabilities Refusal and harm judges, attack success rates under budgets, over-refusal, prompt injection, dangerous-capability and alignment evals, sandbagging, eval awareness and frontier safety policies.

Part IV · Practice

  1. 09Tooling, Production, RAG and Online Evaluation The harness landscape (lm-eval, Inspect, Harbor, verifiers, promptfoo and more), CI regression gates, RAG and hallucination metrics, online judges, A/B tests, SLOs and drift.
  2. 10Capstone: An End-to-End Eval Suite for an Agent and Its RL Environment Build, validate and report a complete eval suite for a tool-using agent and the RL environment that trains it, from error analysis to a CI gate and a results card.

Back matter

  1. RReferences Every source cited in the book, grouped by topic, with links to papers, repositories and articles.

Who this book is for

You are a strong software engineer or ML practitioner who has shipped something with an LLM in it, or trained a model, and you now need to answer “is it better?” with evidence. You do not need a statistics degree: Chapter 5 builds everything from the standard error up. You do need to be comfortable reading Python.

How to read this book

  • In order, the first time. Chapters 1–5 are the toolkit (vocabulary, metrics, datasets, judges, statistics). Chapters 6–8 apply it to agents, RL environments and safety. Chapter 9 is the tooling and production layer, and Chapter 10 puts everything together in one project.
  • Shortcut for agent builders: 1 → 5 (sections on error bars and pass^k) → 6 → 9 → 10.
  • Shortcut for RL and post-training people: 1 → 2 (pass@k) → 5 → 7 → 6 → 10.
  • Callouts mark notes, tips, pitfalls and facts that change quickly (“As of November 2026”).
  • Numbers. Every worked number is reproduced by a script in code/. Numbers from papers are cited inline.

How to run the code

Each chapter has a folder code/chNN/ of small, self-contained Python 3 programs. They use only the standard library and NumPy, need no API keys and no network: models, judges, agents and users are mocked with seeded random generators, so every run prints the same numbers as the book.

python3 -m pip install numpy          # the only dependency
python3 code/ch01/mini_harness.py     # run one example
python3 code/run_all.py               # run every example in the book

Open index.html directly from disk; nothing is loaded from the network. Press t on any chapter to toggle the table of contents.
