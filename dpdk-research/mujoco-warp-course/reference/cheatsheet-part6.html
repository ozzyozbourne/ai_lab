    1Part VI at a glance: one graph per control step

    Part VI turns a working simulation into a fast, extensible one: capture the step in a CUDA graph, know what the graph baked in, tune with measurements, add your own kernels, render and cast rays, hand buffers to PyTorch or JAX, and get derivatives from the worlds themselves.

    2CUDA graphs

    Warm up, capture, replay

    if wp.get_device().is_cuda and not wp.is_conditional_graph_supported():
    m.opt.graph_conditional = False    # CUDA < 12.4: unrolled solver loop
mjw.step(m, d)                         # 1. warm up: compile every kernel
with wp.ScopedCapture() as capture:    # 2. record (does NOT run; d.time unchanged)
    mjw.step(m, d)
graph = capture.graph
for _ in range(1000):
    wp.capture_launch(graph)           # 3. replay: one call
wp.synchronize()

    Ch 24 §2, §6

    A whole control step: my_env.capture_step

    def capture_step(m, d, nsub=1, post=None):
    with wp.ScopedCapture(device=d.qpos.device) as c:
        for _ in range(nsub):
            mjw.step(m, d)
        if post is not None:
            post(m, d)          # reward / done / reset kernels
    return c.graph

    (Abridged; the snapshot also applies the conditional-node fallback.) put_model only warns on CUDA < 12.4 and still sets graph_conditional=True (Ch 24 §8).

    Conditional nodes

    • graph_conditional=True: the solver is a wp.capture_while loop on the device, until the slowest world is done.
    • False: m.opt.iterations unrolled copies; same physics, many more launches.
    • Need CUDA ≥ 12.4 in both toolkit and driver (Ch 24 §5).
    • Warp 1.19 records graphs on CPU too: CPU timings are CPU numbers (§7).

    4Measure, then tune

    A throughput number that means something

    World-steps/s (or ns per world-step), after warm-up, on a captured graph, between two wp.synchronize()-bounded clock reads, at a stated nworld, with zero overflow (Ch 25 §1).

    mjwarp-testspeed model.xml --nworld 8192 --nstep 1000      # GPU only
mjwarp-testspeed model.xml --noise_std 0 --event_trace     # compare with your loop
mjwarp-testspeed model.xml -o "opt.iterations=10" --measure_solver --measure_alloc
mjwarp-testspeed model.xml --replay ctrl.npz --noise_rate 1e-6

    Defaults are part of every number: --nworld 8192, OU ctrl noise (--noise_std 0.01, --noise_rate 0.1) around the keyframe, --function step, abort on overflow (§4, §5).

    Per-stage profile

    from mujoco_warp._src.warp_util import EventTracer   # private API

    5Custom kernels and callbacks

    House style (kernel analyzer rules)

    @wp.kernel
def _height_reward(
  # Model:
  body_mass: wp.array2d[float],
  # Data in:
  xpos_in: wp.array2d[wp.vec3],
  # In:
  bodyid: int,
  # Out:
  reward_out: wp.array[float],
):
  worldid = wp.tid()
  mass = body_mass[worldid % body_mass.shape[0], bodyid]  # "*" field
  reward_out[worldid] = mass * xpos_in[worldid, bodyid][2]

    Data fields get _in/_out, Model fields keep their names; inputs before outputs; no defaults; factories use module="unique" (Ch 26 §1, §12).

    SlotRuns inSemantics

    sensorevery sensor stagefn(m, d, stage)
    contactfiltercollisionclears the CONSTRAINT bit (nacon cannot shrink)

    Ch 26 §3-§5

    More extension points

    • m.opt.run_collision_detection = False: skip collision, keep your contacts; refill them every step (Ch 26 §6).
    • d.userdata: per-world state, zeroed by reset, saved by State.USERDATA (§9).
    • Tiles: wp.launch_tiled, tile_load, tile_sum, tile_store; every lane must reach every tile call (§8).
    • cache_kernel keys are positional hashes + module + name (§7).
    • Reused _src functions are private: pin and test them against MuJoCo C at 1e-5 (§10).

    6Rays and batch rendering

    Rays

    dist, geomid, normal = mjw.ray(m, d, pnt, vec)     # one ray per world, allocates
mjw.rays(m, d, pnt, vec, geomgroup, flg_static, bodyexclude,
         dist, geomid, normal)                       # many rays, preallocated
# pnt, vec: (nworld, nray) vec3; dist == -1 means miss

    Filters: bodyexclude, zero alpha, flg_static, geomgroup mask (all -1 = off). With a render context rc rays walk the scene BVH (Ch 27 §1, §2).

    Render loop

    rc = mjw.create_render_context(mjm, nworld=N, cam_res=(W, H),  # (width, height)
        render_rgb=True, render_depth=True, render_seg=True)
mjw.step(m, d)              # or forward
mjw.refit_bvh(m, d, rc)     # else moved objects vanish
mjw.render(m, d, rc)        # one megakernel, dim=(nworld, total_rays)
mjw.get_rgb(rc, 0, rgb)     # rgb: (N, H, W) vec3; camera 0 = first ACTIVE
mjw.get_depth(rc, 0, 3.0, depth)   # planar depth / 3.0, clamped

    Ch 27 §4, §11

    Context options worth knowing

    • Pass every option as a keyword. enabled_geom_groups=[0, 1, 2]: groups 3+ are invisible by default.
    • use_shadows=False (0.3 of the light when on), samples_per_pixel=1 (n² supersampling), use_textures=True, render_skybox=False.
    • Per-world FOV needs use_precomputed_rays=False; changing a flag means a new context.
    • Hand-written cameras go after step, before refit/render, every frame. Refit and render can be captured.

    7PyTorch and JAX

    PyTorch: zero-copy views

    qpos_t = wp.to_torch(d.qpos)       # same data_ptr; make once, reuse
ctrl_t = wp.to_torch(d.ctrl)
ctrl_t.copy_(actions.float())      # actions IN: copy, never rebind d.ctrl
obs = wp.from_torch(obs_t)         # keeps a reference to obs_t
    • float32 everywhere; vector dtypes become trailing dims; quats stay (w, x, y, z).
    • wp.copy only checks element byte size: int32 ↔ uint32 reinterpret silently; float64/int64 raise.
    • A non-default torch.cuda.Stream() needs wp.stream_from_torch or an explicit wait.

    JAX: wp.jax_callable

    import os                      # BEFORE import jax
os.environ["XLA_FLAGS"] = "--xla_gpu_graph_min_graph_size=1"
os.environ["XLA_PYTHON_CLIENT_ALLOCATOR"] = "platform"
os.environ["XLA_PYTHON_CLIENT_PREALLOCATE"] = "false"
import jax

def warp_step(qpos_in: wp.array2d[float], qvel_in: wp.array2d[float],
              qpos_out: wp.array2d[float], qvel_out: wp.array2d[float]):
    wp.copy(d.qpos, qpos_in); wp.copy(d.qvel, qvel_in)
    mjw.step(m, d)
    wp.copy(qpos_out, d.qpos); wp.copy(qvel_out, d.qvel)

step_fn = wp.jax_callable(warp_step, num_outputs=2,
    graph_mode=wp.JaxCallableGraphMode.WARP,
    output_dims={"qpos_out": (NWORLD, mjm.nq), "qvel_out": (NWORLD, mjm.nv)})
# unroll with jax.lax.scan inside jax.jit; NWORLD is fixed

    Set graph_conditional explicitly; in WARP mode the Python body runs only at capture. On CPU, graph mode NONE works. MJX impl="warp" is the official JAX route (Ch 28 §4, §5, §8).

    8Derivatives, CEM and system identification

    What works in 4.0.1

    • wp.Tape works for your own kernels: forward under the tape, seed .grad, backward(), read input .grad, zero().
    • Every public mjw function is wrapped by diff._wrap with no adjoint rule (diff.RULES[name] is None): any MJWarp call inside an active tape raises NotImplementedError. Keep simulation outside the tape.
    • register_adjoint declares arrays and fields, an optional supported hook and a backward (Ch 29 §4).

    Ch 29 §2, §3

    Finite differences across worlds

    # 2k + 1 worlds: base, +h e_i, -h e_i for k parameters
p = np.tile(p0, (2 * k + 1, 1))
for i in range(k):
    p[1 + i, i] += h; p[1 + k + i, i] -= h
# write p into batched Model fields, roll out once, then
J[:, i] = (y[1 + i] - y[1 + k + i]) / (2 * h)

    float32: start with h ≈ 1e-2 of the input scale and check its neighbours (Ch 29 §5).

    CEM and parallel system ID

    • CEM: sample, roll out all at once, keep elites, refit. Snapshot with State.PHYSICS (+ TIME, + WARMSTART with contacts) (§6).
    • System ID: one world per candidate in batched Model fields, set_const eagerly after mass writes, loss on the device, full covariance for correlated parameters, stop at the noise floor (§7).

    9An on-device RL environment

    Rules of the env

    • One captured graph per control step (Figure 1); the host copies actions in and reads statistics once per iteration.
    • Report terminated and truncated separately; keep final_obs (auto-reset overwrites obs; truncations need a value bootstrap) (Ch 30 §5).
    • In-graph DR only for fields without derived quantities; mass via eager set_const at rollout boundaries.
    • Observe from qpos/qvel: sensors are computed before integration and zeroed by reset.

    Workflow

    1. Test reward kernels against NumPy.
    2. Baseline first (evolution strategies), then the reference PPO (§6, §7).
    3. Read the learning curve before tuning; tune normalizer, clipping, learning rate first (§8).
    4. Contact tasks: size naconmax and njmax from measurements, sweep the solver, monitor overflow in a copy that survives auto-reset (§10).

    10Pitfalls

    • Changing a Python-valued option after capture does nothing to the graph; recapture (and maybe recompile).
    • Replacing an array after capture: the graph reads the old address. Applies to d.ctrl, m.opt.* and torch views.
    • CUDA < 12.4: set m.opt.graph_conditional = False before capture; put_model only warns.
    • Python side effects in callbacks run once, at capture time.
    • Timing CPU graphs says nothing about GPU performance; never quote it as such.
    • Forgetting refit_bvh makes moved objects vanish from the image: the BVH still has the old boxes.
    • Installing JAX on Colab can break the matched jax/jaxlib/CUDA plugin; use the preinstalled one. Setting XLA variables after import jax is ignored.
    • MJWarp calls inside wp.Tape raise in 4.0.1; use finite differences across worlds.
    • A stale snapshot of .numpy(): it is a copy, not a view (on GPU); use wp.to_torch for live views.
