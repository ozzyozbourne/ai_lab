The tree never touches the file. It asks the buffer pool for a page id, gets a pinned frame, changes it, and unpins it as dirty. This page shows every one of those calls during a put. Text of the chapter: README.md. First page: the tree of pages.

The buffer pool during an insert that splits

The figure starts where part 4 of the chapter's programs starts: the first 11 scenario keys are in the tree and the tree has been flushed, so every frame is clean. Put next scenario key inserts key 15, which splits leaf page 2. Watch three things. At most two pages are pinned at once. With the 2 frames chosen here, the pool must evict the dirty left half (page 2) to fetch the parent, so half of the split reaches the file before the parent has changed. The other changed pages stay dirty in memory until Flush writes them one by one. With 3 or more frames the put writes only the new zero-filled page. A new operation always starts from the state after the operation you are looking at has finished.
