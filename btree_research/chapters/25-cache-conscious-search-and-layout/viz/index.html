Inside a page the unit of cost is the 64-byte cache line, and every unpredictable if is a guess the CPU can get wrong. Watch five ways to find the same key and count the lines each one touches. Text and code: chapter 25 README.

1. One lookup, step by step

Each box is one cache line holding eight 8-byte keys. Pick an algorithm and a needle (a whole number), then step. The answer is always the lower bound: the position of the first key that is not smaller than the needle. The Eytzinger layout and the block tree keep their keys in a different order, so they finish by reading one entry of a second array, rank, that maps a slot back to the sorted position: that is one more cache line, and it is counted. In the block tree every line is a node; its label says whose child it is. Tick Predict to be asked before each comparison.

2. The same lookup in all five

One small square per cache line of each algorithm's key array; filled squares were read. "Lines read" adds the line of the rank array where the algorithm has one. Below it, the average over 1000 seeded random needles: these are the numbers the Zig and Rust programs print.

3. What prefetch changes

4095 keys, 1000 lookups. A line that is read without having been hinted is a miss the CPU has to sit through before it can even compute the next address. Prefetch does not reduce the lines read; it makes the key lines after the first one start loading early. A hint only counts if at least one comparison separates it from the read. The Eytzinger rows include the one rank line, which nothing prefetches.
