1What is a port?

To an application, a port is a number. Every Ethernet device that DPDK finds gets a uint16_t port_id starting at 0, up to RTE_MAX_ETHPORTS (a build-time constant). Each call in lib/ethdev/rte_ethdev.h takes that number as its first argument. Behind the number there is always a poll mode driver (PMD): the code that knows how this particular device moves packets. For an Intel NIC it is net_ice or similar, talking to hardware registers through VFIO; for the devices in this chapter it is a few hundred lines of software in drivers/net/null, drivers/net/ring or drivers/net/tap. Your code does not change when the PMD does, which is why the whole course can run on a laptop.

Ports appear during rte_eal_init(). The EAL scans its buses: the PCI bus finds NICs bound to vfio-pci, and the virtual-device bus creates one port per --vdev= option. We always pass --no-pci on this machine (its only NIC carries the session's network and must stay with the kernel), so every port here comes from --vdev. How buses, probing and device arguments work is ch9.

Finding ports and their names

  • rte_eth_dev_count_avail() returns how many ports are usable. RTE_ETH_FOREACH_DEV(p) loops over their ids. It skips ports that are owned by someone else, for example the member ports that a bonding or failsafe PMD has taken over (ch12), so do not assume ids are 0, 1, 2 without gaps (exercise 1).
  • rte_eth_dev_get_name_by_port(port, name, size) gives the device name, such as "net_null0". 26.11 added the size argument; two-argument code from older tutorials no longer compiles. rte_eth_dev_get_port_by_name() goes the other way. RTE_ETH_NAME_MAX_LEN is always a big enough buffer.
  • rte_eth_dev_is_valid_port(port) returns 1 for a port that exists; after rte_eth_dev_close() it returns 0.
  • rte_eth_dev_socket_id(port) is the NUMA node the device is attached to, or SOCKET_ID_ANY (-1) when unknown; pass it to the queue setup calls so queue memory lands near the device.

2The port lifecycle

A probed port cannot move packets yet. You must tell it how many queues you want, give each receive queue a mempool to take buffers from, and start it. The order is fixed:

  1. rte_eth_dev_configure(port, nb_rxq, nb_txq, &conf) sets the number of receive and transmit queues and the port-wide configuration. An all-zero struct rte_eth_conf is valid and means: no RSS, no offloads, default MTU (1500). ethdev checks the counts against max_rx_queues/max_tx_queues and every requested offload against the capability masks, records everything in the device's shared data and calls the PMD's dev_configure. 26.11 detail: asking for RSS (rxmode.mq_mode = RTE_ETH_MQ_RX_RSS) with more than one Rx queue on a PMD that reports no flow_type_rss_offloads is now rejected; mask rss_hf with the capability (ch15).
  2. rte_eth_rx_queue_setup(port, q, nb_desc, socket, rxconf, mempool) once per Rx queue and rte_eth_tx_queue_setup(port, q, nb_desc, socket, txconf) once per Tx queue. nb_desc is the ring size in descriptors (section 3); 0 means "the driver's default". socket is where to allocate the ring, normally rte_eth_dev_socket_id(port). rxconf/txconf may be NULL, meaning info.default_rxconf/default_txconf. The mempool is where the PMD gets every receive buffer from, for the lifetime of the queue.
  3. rte_eth_dev_adjust_nb_rx_tx_desc(port, &nb_rxd, &nb_txd), between the two steps above, clamps your ring sizes to rx_desc_lim/tx_desc_lim and rounds them to nb_align. Calling it costs nothing and turns a startup failure on unknown hardware into a smaller ring.
  4. rte_eth_dev_start(port) calls the PMD's dev_start, re-applies MAC addresses and promiscuous/all-multicast settings, and then, as its last step, copies the PMD's burst functions into the fast-path table (eth_dev_fp_ops_setup(), section 5). From this moment rte_eth_rx_burst() reaches the driver.
  5. rte_eth_dev_stop(port) first puts dummy functions back into the fast-path table, then calls the PMD's dev_stop. Configuration and queues are kept; you may reconfigure, set queues up again, or start again.
  6. rte_eth_dev_close(port) (only when stopped) frees the queues and the driver's private data and releases the port id.

3Descriptor rings in one picture

What is a "queue" on a real NIC, and what does nb_desc count? A receive queue is a descriptor ring: an array of nb_desc small records in memory that both the NIC and the PMD can read and write. Each descriptor holds the physical (IOVA, ch4) address of one empty mbuf data buffer. The NIC and the software chase each other around the ring:

  • The NIC owns the head. When a frame arrives it takes the next descriptor, DMAs the frame into that buffer, writes the length, checksum status, RSS hash and so on back into the descriptor, and sets its DD bit ("descriptor done").
  • The software owns the tail. rte_eth_rx_burst() is the PMD looking at descriptors from its tail onwards: every descriptor with DD set is a received packet. For each one it allocates a fresh mbuf from the queue's mempool, writes the new buffer's address into the descriptor (refill or re-arm), and hands the full mbuf to you. Now and then it tells the NIC how far it has refilled by writing a tail register.
  • If frames arrive faster than the application polls, the NIC catches up with the tail and finds no armed descriptor. It must drop the frame and counts it: that is imissed in rte_eth_stats. If the mempool is empty, the refill fails: the PMD stops, leaves the packet in the ring and counts rx_nombuf; soon afterwards the ring fills and imissed rises too.

So nb_desc is how many packets the NIC can buffer while your lcore is busy elsewhere. A bigger ring absorbs longer gaps (bursts, a slow packet, a page fault) at the cost of memory and cache footprint. Transmit rings work the same way in reverse: the PMD fills descriptors and bumps the tail, the NIC sends and marks them done, and the PMD frees the sent mbufs later, in batches, when it needs the slots again. The full hardware view, with real descriptor formats and thresholds, is ch23.

4The burst API and who owns which mbuf

The two functions that move packets are deliberately simple:

uint16_t rte_eth_rx_burst(uint16_t port_id, uint16_t queue_id,
                          struct rte_mbuf **rx_pkts, const uint16_t nb_pkts);
uint16_t rte_eth_tx_burst(uint16_t port_id, uint16_t queue_id,
                          struct rte_mbuf **tx_pkts, uint16_t nb_pkts);
  • rte_eth_rx_burst() never blocks. It returns between 0 and nb_pkts packets that are ready now and writes their mbuf pointers into rx_pkts[0..n-1]. Returning fewer than you asked for, including 0, is normal and is not an error. From that moment the application owns those mbufs: it must pass each one on (to tx_burst, a ring, another library) or free it. The header asks for nb_pkts divisible by 8 "to work with any driver", because vector receive paths process descriptors 4 or 8 at a time.
  • rte_eth_tx_burst() may accept fewer packets than you offer. It returns how many it placed in the transmit ring, always a prefix: tx_pkts[0..ret-1] now belong to the PMD, which frees them after the NIC has sent them. tx_pkts[ret..nb_pkts-1] are still yours. Free them, retry them later, or count them as drops; forgetting them is the classic DPDK leak.
  • One queue, one lcore. The burst functions take no locks. Two lcores may poll different queues of the same port in parallel, but never the same queue, unless the PMD advertises RTE_ETH_TX_OFFLOAD_MT_LOCKFREE (net_null does). Multi-queue designs are ch15.
  • Polling means 100% CPU. The forwarding loop calls rx_burst forever, even when it returns 0, so top shows the lcore at 100% on an idle link. That is by design; ch22 covers interrupt and power-saving modes.

The loop repeats four steps: rx_burst (buffers leave the Rx ring, the PMD refills it from the pool), tx_burst (as many as fit go into the Tx ring), handle the unsent tail, and the NIC sends some packets so the PMD can free them. With "NIC sends" lower than the burst size the Tx ring stays full and tx_burst refuses part of every burst. Untick free the unsent tail: refused mbufs fall onto the leak pile, the pool drains, refills start failing and the receive side stops. Nothing crashes; the port just goes quiet.

6Burst size, batching and the Tx buffer

Every call costs something whatever it carries: the fp_ops lookup, the indirect call, the driver's setup, and on a real NIC the MMIO write of the tail register, which can cost more than the rest together. Passing many packets per call spreads that fixed cost. A simple model is cycles per packet = a / B + c, where B is the burst size, a the fixed cost of one rx+tx call pair and c the cost of each packet. burst_sweep.c measures the rx→tx loop on a net_null port for B = 1 to 128:

Sizing the mempool for a port

Every Rx descriptor holds an mbuf all the time (it is armed with one), every Tx descriptor can hold one until the PMD frees it, every lcore's mempool cache can hide up to cache_size of them (ch6), and the loop holds one burst. So the pool needs at least

nb_ports × (nb_rxd + nb_txd) + nb_lcores × (cache_size + burst)

For two ports with 1024 + 1024 descriptors, one lcore, cache 250 and a 256-entry burst array that is 2 × 2048 + 506 = 4602, which my_skeleton rounds up to 213 − 1 = 8191 (the best size for a ring-backed pool, ch6). Too small a pool does not fail at startup: it shows up later as rx_nombuf and imissed.

static int
port_init(uint16_t port, struct rte_mempool *mp)
{
	struct rte_eth_conf conf;
	struct rte_eth_dev_info info;
	struct rte_eth_txconf txconf;
	uint16_t nb_rxd = NB_RXD, nb_txd = NB_TXD;
	int ret;

	if (!rte_eth_dev_is_valid_port(port))
		return -EINVAL;

	ret = rte_eth_dev_info_get(port, &info);
	if (ret != 0)
		return ret;

	/* An all-zero rte_eth_conf means: no RSS, no offloads, default MTU. */
	memset(&conf, 0, sizeof(conf));
	/* MBUF_FAST_FREE: we promise all mbufs come from one pool and have
	 * refcnt 1, so the PMD may free them in bulk. Only ask if supported. */
	if (info.tx_offload_capa & RTE_ETH_TX_OFFLOAD_MBUF_FAST_FREE)
		conf.txmode.offloads |= RTE_ETH_TX_OFFLOAD_MBUF_FAST_FREE;

	/* 1 Rx queue and 1 Tx queue. */
	ret = rte_eth_dev_configure(port, 1, 1, &conf);
	if (ret != 0)
		return ret;

	/* Clamp the ring sizes to what the PMD supports. */
	ret = rte_eth_dev_adjust_nb_rx_tx_desc(port, &nb_rxd, &nb_txd);
	if (ret != 0)
		return ret;

	/* Rx queue 0: the PMD fills its descriptors with mbufs from mp. Put the
	 * queue memory on the NIC's NUMA node (SOCKET_ID_ANY if unknown). */
	ret = rte_eth_rx_queue_setup(port, 0, nb_rxd, rte_eth_dev_socket_id(port),
				     NULL, mp);
	if (ret < 0)
		return ret;

	/* Tx queue 0: start from the PMD's defaults, add our port offloads. */
	txconf = info.default_txconf;
	txconf.offloads = conf.txmode.offloads;
	ret = rte_eth_tx_queue_setup(port, 0, nb_txd, rte_eth_dev_socket_id(port),
				     &txconf);
	if (ret < 0)
		return ret;

	if (use_txbuf) {
		/* A Tx buffer for this port (it is the *destination* buffer). */
		txb[port] = rte_zmalloc_socket("txbuf", RTE_ETH_TX_BUFFER_SIZE(TXBUF_SIZE),
					       0, rte_eth_dev_socket_id(port));
		if (txb[port] == NULL)
			return -ENOMEM;
		rte_eth_tx_buffer_init(txb[port], TXBUF_SIZE);
		rte_eth_tx_buffer_set_err_callback(txb[port], txbuf_unsent,
						   &st[port].dropped);
	}

	/* Start: from here on rte_eth_fp_ops[port] points at the PMD. */
	ret = rte_eth_dev_start(port);
	if (ret < 0)
		return ret;

	struct rte_ether_addr mac;
	ret = rte_eth_macaddr_get(port, &mac);
	if (ret != 0)
		return ret;
	printf("Port %u (%s): MAC " RTE_ETHER_ADDR_PRT_FMT ", %u rxd, %u txd\n",
	       port, info.driver_name, RTE_ETHER_ADDR_BYTES(&mac), nb_rxd, nb_txd);

	/* Accept every frame, not only those for our MAC. Some PMDs (net_null)
	 * are always promiscuous and return -ENOTSUP for *disable*; enable is
	 * fine everywhere here. */
	return rte_eth_promiscuous_enable(port);
}
lcore_main(void)
{
	struct rte_mbuf *bufs[MAX_BURST];
	const uint64_t hz = rte_get_tsc_hz();
	const uint64_t drain = hz * DRAIN_US / 1000000;
	uint64_t start = rte_get_tsc_cycles(), next_print = start + hz, last_drain = start;
	uint16_t port;

	printf("\nlcore %u forwarding (burst %u, %s). Ctrl+C to quit.\n",
	       rte_lcore_id(), burst, use_txbuf ? "tx buffer" : "direct tx_burst");

	while (!force_quit) {
		RTE_ETH_FOREACH_DEV(port) {
			uint16_t dst = port ^ 1;      /* 0<->1, 2<->3, ... */

			/* rx_burst returns 0..burst mbufs that are now OURS. */
			uint16_t nb_rx = rte_eth_rx_burst(port, 0, bufs, burst);
			if (unlikely(nb_rx == 0))
				continue;
			st[port].rx += nb_rx;

			if (!use_txbuf) {
				/* tx_burst may accept fewer than asked. It now
				 * owns bufs[0..nb_tx-1]; we still own the rest. */
				uint16_t nb_tx = rte_eth_tx_burst(dst, 0, bufs, nb_rx);
				st[dst].tx += nb_tx;
				st[dst].tx_calls++;
				if (unlikely(nb_tx < nb_rx)) {
					st[dst].dropped += nb_rx - nb_tx;
					rte_pktmbuf_free_bulk(&bufs[nb_tx], nb_rx - nb_tx);
				}
			} else {
				/* One packet at a time into the buffer; a flush
				 * (= one tx_burst) happens when it is full. The
				 * return value is how many that flush sent. */
				for (uint16_t i = 0; i < nb_rx; i++) {
					uint16_t sent = rte_eth_tx_buffer(dst, 0, txb[dst], bufs[i]);
					if (sent) {
						st[dst].tx += sent;
						st[dst].tx_calls++;
					}
				}
			}
		}

		uint64_t now = rte_get_tsc_cycles();
		/* Drain timer: never leave packets in a half-full buffer for long. */
		if (use_txbuf && now - last_drain > drain) {
			RTE_ETH_FOREACH_DEV(port) {
				uint16_t sent = rte_eth_tx_buffer_flush(port, 0, txb[port]);
				if (sent) {
					st[port].tx += sent;
					st[port].tx_calls++;
				}
			}
			last_drain = now;
		}
		if (now >= next_print) {
			print_stats((double)(now - start) / hz);
			next_print += hz;
		}
	}
}
	/* We forward p <-> p^1, so we need an even, non-zero number of ports. */
	nb_ports = rte_eth_dev_count_avail();
	if (nb_ports < 2 || (nb_ports & 1))
		rte_exit(EXIT_FAILURE, "need an even number of ports (>= 2), found %u\n",
			 nb_ports);

	/* Pool sizing: every descriptor can hold an mbuf, plus each lcore's
	 * cache and one burst in flight. Rounded up to 2^n - 1 for the ring. */
	unsigned need = nb_ports * (NB_RXD + NB_TXD) +
			rte_lcore_count() * (CACHE_SIZE + MAX_BURST) +
			(use_txbuf ? nb_ports * TXBUF_SIZE : 0);
	unsigned nb_mbufs = rte_align32pow2(need + 1) - 1;
	printf("mbuf pool: need %u -> creating %u mbufs (%u ports)\n",
	       need, nb_mbufs, nb_ports);
	struct rte_mempool *mp = rte_pktmbuf_pool_create("ch08_skel", nb_mbufs,
			CACHE_SIZE, 0, RTE_MBUF_DEFAULT_BUF_SIZE, rte_socket_id());
	if (mp == NULL)
		rte_exit(EXIT_FAILURE, "cannot create mbuf pool: %s\n",
			 rte_strerror(rte_errno));

	RTE_ETH_FOREACH_DEV(port) {
		ret = port_init(port, mp);
		if (ret != 0)
			rte_exit(EXIT_FAILURE, "port %u init failed: %s\n",
				 port, rte_strerror(-ret));
	}

	if (rte_lcore_count() > 1)
		printf("note: only the main lcore forwards; other lcores idle.\n");

	lcore_main();

	/* Graceful shutdown: flush buffers, stop (fast path -> dummies), close.
	 * Stopping a port makes the PMD give back the mbufs held by its rings. */
	uint16_t ids[RTE_MAX_ETHPORTS], cnt = 0;
	RTE_ETH_FOREACH_DEV(port)
		ids[cnt++] = port;
	for (uint16_t i = 0; i < cnt; i++) {
		port = ids[i];
		if (use_txbuf) {
			rte_eth_tx_buffer_flush(port, 0, txb[port]);
			rte_free(txb[port]);
		}
		printf("port %u: app rx=%" PRIu64 " tx=%" PRIu64 " dropped=%" PRIu64
		       " tx_burst calls=%" PRIu64 "\n", port, st[port].rx, st[port].tx,
		       st[port].dropped, st[port].tx_calls);
		ret = rte_eth_dev_stop(port);
		if (ret != 0)
			printf("rte_eth_dev_stop(%u): %s\n", port, rte_strerror(-ret));
		rte_eth_dev_close(port);
	}
	printf("mbufs back in pool: %u of %u%s\n", rte_mempool_avail_count(mp),
	       nb_mbufs, rte_mempool_avail_count(mp) == nb_mbufs ? " (no leak)" : " (LEAK!)");
	rte_mempool_free(mp);
	rte_eal_cleanup();
	return 0;
}

8Link, MAC and the 26.11 statistics model

  • rte_eth_link_get_nowait(port, &link) reads struct rte_eth_link (speed, duplex, autoneg, status) without waiting; rte_eth_link_get() may wait up to several seconds for autonegotiation on a real NIC, so keep it out of the fast path. rte_eth_link_to_str() formats it: Link up at 10 Gbps FDX Fixed None for the virtual ports here. Both are marked "warn unused result": check the return value.
  • rte_eth_macaddr_get() gives the port's MAC (net_null and net_tap make up a random one, net_ring reports zeros). rte_eth_promiscuous_enable() makes the port accept frames for any destination MAC; forwarders need it, and forgetting it is why "testpmd receives but my app does not" on net_tap (testpmd enables it by default).
  • rte_eth_stats_get(port, &st) fills struct rte_eth_stats. In 26.11 it contains only port totals: ipackets, opackets, ibytes, obytes, imissed, ierrors, oerrors, rx_nombuf. The per-queue arrays (q_ipackets[]...) and the queue-stats mapping API are gone; per-queue counters are now extended statistics (xstats) with names like rx_q0_packets. Port control, xstats by id, events and live reconfiguration are ch12.

When it doesn't work: a five-step checklist
  1. Common pitfalls

  • The pool slowly empties and the port goes quiet: the unsent tail of rte_eth_tx_burst() is never freed. Always handle nb_tx < nb_rx. Watch rte_mempool_avail_count() and rx_nombuf.
  • "My app receives nothing" and no error: the port was never started, or was stopped, so the dummy burst function returns 0. Look for the not ready port log line and check rte_errno.
  • Queue setup before configure: -EINVAL on some PMDs, a segmentation fault on net_null in 26.11. Configure first, always.
  • Starting a port with queues not set up returns 0: ethdev does not check. Set up every queue you configured.
  • A descriptor count that works on net_null fails on hardware: software PMDs have no limits. Use rte_eth_dev_adjust_nb_rx_tx_desc().
  • Two lcores polling the same queue: corrupted rings, lost or duplicated mbufs, no error. One queue per lcore (ch15), unless the PMD says MT_LOCKFREE.
  • Packets stuck in a Tx buffer: rte_eth_tx_buffer() only sends when the buffer is full. Add a drain timer and flush on shutdown.
  • Old code does not compile: rte_eth_dev_get_name_by_port() takes a size in 26.11; struct rte_eth_stats has no q_ipackets[]; flags use the RTE_ETH_ prefix.
  • Hand-written app on net_tap sees no kernel traffic: promiscuous mode is off by default. Call rte_eth_promiscuous_enable().
  • Stopping a port while an lcore is still in rx_burst: undefined. Signal the lcores, wait for them, then stop.

Summary
  • A port is a uint16_t id backed by a PMD. Discover ports with rte_eth_dev_count_avail() and RTE_ETH_FOREACH_DEV, and read rte_eth_dev_info_get() before choosing queue counts, ring sizes or offloads.
  • Lifecycle: configure → (adjust) → rx/tx queue setup → start → stop → close. Started ports refuse reconfiguration (-EBUSY); some mistakes are not checked at all, so follow the order.
  • rx_burst hands you 0..n mbufs that you now own; tx_burst takes a prefix and leaves the rest with you. Free the unsent tail.
  • A burst call is two loads and an indirect call through rte_eth_fp_ops[port], with no validity checks. Start installs the PMD's functions; stop installs dummies that return 0.
  • An Rx queue is a descriptor ring the NIC fills from the head and the PMD empties and refills from the tail. Polling too slowly shows up as imissed, an empty pool as rx_nombuf.
  • Batching shares the fixed cost of each call (measured here: about 50 cycles/packet at burst 1, under 20 at burst 8 on net_null). rte_eth_tx_buffer batches single packets but needs a drain timer.
  • In 26.11 rte_eth_stats holds port totals only; per-queue counters are xstats.
